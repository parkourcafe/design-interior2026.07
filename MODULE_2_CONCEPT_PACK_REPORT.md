## Что сделано

- Добавлена чистая функция `buildConceptPackFromPassport(...)`.
- Входы: паспорт, whitelist-данные ответов, принятые risk cards, scope/package и наличие КП.
- Выходы:
  - summary проекта;
  - style direction;
  - текстовая структура мудборда и запросы для поиска референсов;
  - направление палитры и материалов;
  - concept notes по комнатам и зонам;
  - внутренние заметки дизайнеру;
  - client-ready summary;
  - плоский массив `concept_sections` для дальнейших представлений.
- Сборка детерминированная: без LLM, сети, image generation, анализа файлов и внешних интеграций.
- Контактные данные и город не копируются в pack; email, телефон и `@handle` маскируются, если случайно попали в свободный текст.
- Результат проверяется строгой Zod-схемой до записи и после чтения.

## Хранение и доступ

- Migration `0008_concept_packs.sql` создаёт одну 1:1 таблицу `concept_packs`.
- Весь pack хранится одним JSONB в `content`; отдельная таблица секций для MVP не нужна.
- `project_id` — primary key и FK с `on delete cascade`.
- RLS повторяет studio-доступ Module 1 через `is_studio_member(...)`.
- Anon-policy, public token и клиентский route отсутствуют.
- `projects.status` не меняется, поэтому Review Board и Proposal flow Module 1 остаются прежними.
- При создании pack и идемпотентное событие `concept_pack_created` пишутся атомарно DB-trigger'ом; action дополнительно проверяет audit entry.

## UI

- На Review Board готового проекта появилась карточка «Создать Concept Pack».
- После создания действие меняется на «Открыть Concept Pack».
- Приватная страница: `/dashboard/projects/[id]/concept-pack`.
- Страница показывает summary, стиль, палитру, moodboard outline, комнаты/зоны, внутренние заметки и копируемое резюме для клиента.
- Публичной клиентской страницы Concept Pack нет.

## Как проверить вручную за 5 минут

1. Применить Supabase migration `0008_concept_packs.sql`.
2. Войти дизайнером или участником студии и открыть проект с завершённым брифом.
3. Принять одну или несколько risk cards.
4. Нажать «Создать Concept Pack» и убедиться, что открылась приватная страница pack.
5. Вернуться в проект: кнопка должна стать «Открыть Concept Pack».
6. В Supabase проверить одну строку `concept_packs` и одно событие `concept_pack_created` для проекта.
7. Под другой студией прямой URL должен вернуть 404 через RLS.

## Автопроверки

- Unit tests проверяют полную сборку, fallback на неполном паспорте, package precedence, отсутствие мутаций, стабильный порядок risk cards, PII masking и strict schema.
- `npm run test` — зелёный, 15 файлов / 74 теста.
- `npm run typecheck` — зелёный.
- `npm run lint` — зелёный.
- `npm run build` — зелёный, включая приватный route `/dashboard/projects/[id]/concept-pack`.

## Известные ограничения MVP

- Pack read-only и один на проект; редактор, версии и ручная пересборка не входят в этот slice.
- Текущая таблица `proposals` не хранит структурный snapshot выбранного package: pack рассчитывает package тем же детерминированным resolver'ом из актуального паспорта, ответов и принятых рисков, а сохранённые scope-секции КП переносит во внутренние заметки для сверки.
- Moodboard — только текстовый outline и поисковые формулировки; изображения не создаются.
- Конкретные бренды, SKU, спецификации, рендеры и интеграции с дизайнерскими инструментами не создаются.
- Client-ready summary можно скопировать, но он намеренно не опубликован как клиентский портал.
