# DEMO — сквозной сценарий: от intake-ссылки до отправленного КП

Демо русскоязычного pre-sale контура: **Бриф → Цена → КП**.

## Подготовка (один раз)

1. `.env.local` заполнен реальными значениями (шаблон — `.env.example`):
   - Supabase: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
   - Yandex Cloud: `YC_FOLDER_ID`, `YC_API_KEY` (`LLM_PROVIDER=yandex`, `LLM_MODEL=yandexgpt-lite`).
   - `NEXT_PUBLIC_APP_URL` (для локали — `http://localhost:3000`).
2. Для локальной disposable-базы прогнать `tests/db2/run.zsh` (PG16) или
   `PI_DB_IMAGE=postgres:17-alpine tests/db2/run.zsh`. Production adoption
   выполняется только по отдельному checklist и migration-path решению.
3. `npm run seed` — демо-дизайнер `demo@studio.ru` с готовыми `pricing` и `proposal_defaults`.
4. `npm run dev`.

## Сценарий

### 1. Вход дизайнера
- `/login` → email `demo@studio.ru` → magic link → `/dashboard`.

### 2. (Опц.) Настройка
- `/dashboard/setup` — проверить/поправить ставки в pricing-мастере или выключить «считать цену» (режим «без цены»). Настроить exclusions и лимит правок для КП.

### 3. Создание проекта и intake-ссылка
- На `/dashboard` — «Новый проект», имя клиента → создаётся проект, событие `intake_link_created`.
- На странице проекта — блок со ссылкой `/i/<token>`, кнопка «Скопировать».

### 4. Клиент проходит бриф (в приватном окне, без регистрации)
- Открыть `/i/<token>` → «Начать» (событие `brief_started`).
- Пройти ~10 вопросов: тип объекта/площадь/город, горизонт актива, домохозяйство, утро, готовка (+ветка «на скольких»), хранение, бюджет, сроки, стиль (референсы + анти), pain points. Опц. — загрузить план/фото.
- «Завершить» (событие `brief_completed`): строится паспорт, гоняется пайплайн rules + LLM, сохраняются карточки.

### 5. Дизайнер на Review Board
- Обновить `/dashboard/projects/<id>`: паспорт в читаемом виде, карточки рисков (6 полей, тон «Возможный риск…»), недостающие данные.
- **Принять** релевантные карточки, **отклонить** лишние. В «вопросах к первой встрече» появляются `designer_action` принятых карточек.
- Если LLM недоступен — виден баннер деградации, но работают rule-карточки.

### 6. Сборка КП
- «Собрать коммерческое предложение» → `/dashboard/projects/<id>/proposal` (событие `proposal_created`, статус `proposal_draft`).
- Секции предзаполнены из паспорта + принятых карточек + `proposal_defaults`. Блок «Стоимость» — диапазон с разбивкой (или отсутствует в режиме «без цены»).
- Отредактировать секции → «Сохранить».

### 7. Публикация и отправка
- Открыть публичную ссылку `/p/<public_token>` — клиентский вид КП; «Печать / PDF» (через `@media print`).
- «Отправить» → статус `proposal_sent`, событие `proposal_sent` (**activation-метрика**).

## Проверка событий (метрики)

В таблице `events` за сценарий появятся: `intake_link_created` → `brief_started` → `brief_completed` → `proposal_created` → `proposal_sent`.

## Быстрые проверки без БД

- `npm run test` — 43 unit-теста (паспорт, правила, ветвление, дедуп, парсер LLM, цена, КП, review).
- `npx tsx eval/run-eval.ts` → `eval/phase1_results.md` — 9 профилей бриф→карточки.
- `npm run build` · `npm run lint` · `npm run typecheck` — зелёные.

# DEMO M2 — «Планировки»: 10 минут от габаритов до согласованного варианта

Сценарий сдачи M2 по §8.6 позиционирования (DEC-023). Показывает третью
часть формулы: **что решили → как выглядит → во что обошлось** — и завершается
фиксацией версии и обменным DXF. Прогоняется на живой сборке перед показом.

## Подготовка (один раз)

1. Всё из подготовки M1 выше, плюс `ARCHIDOM_LAYOUT_STUDIO_ENABLED=true` в `.env.local`.
2. В контуре рабочих пространств существует организация → проект → активный
   пакет, и у показывающего есть к ним доступ (`/dashboard/projectceo` их видит).
   Для клиентского шага — приглашение с ролью «Заказчик» на пакет.
3. Словарь показа: редактор называем **«Планировки»**. Слова «CAD» в показе нет.

## Сценарий (минуты — ориентир)

### 1–2. Планировка с нуля
- Проект → «Планировки» → создать: название «Кухня-гостиная», ширина × глубина ×
  высота в мм → открывается редактор с коробкой стен.
- Сказать: *«Это не рисунок — это запись решения. Всё, что здесь появится,
  попадёт в зафиксированную версию»*.

### 3–4. Правки и рисование
- Инструментом «Стена» дорисовать перегородку: щелчок — угол, щелчок — стена;
  привязка к узлам и сетке 50 мм видна на статусе.
- Добавить объект (стол/оборудование), в инспекторе поправить размер.
- Отменить и вернуть правку (undo/redo) — история работает; черновик
  сохраняется на сервере сам (подпись «Черновик сохранён на сервере»).

### 5. Привязка к рабочему пространству
- Панель «Рабочее пространство» → «Привязать к пакету» → выбрать пакет,
  идентификатор комнаты предложится из названия, роль — «Основной».
- Сказать: *«Комната появится в момент первой публикации — реестров и лишних
  форм здесь нет»*.

### 6. «Во что обошлось»
- Панель «Во что обошлось» → добавить 2–3 материала с ценами (керамогранит,
  м², цена за единицу × количество). Итог варианта пересчитывается на глазах;
  если задана рамка бюджета пакета — видно «в рамке / выход на N ₽».
- Сказать: *«Цены — целые рубли, итог — арифметика, не оценка ИИ»*.

### 7. Фиксация версии
- «Опубликовать версию» → в истории появляется строка **«Версия V1 ·
  зафиксирована ‹дата›»**; подпись — в свёрнутых «деталях для проверяющих».
- Сказать: *«Зафиксированную версию нельзя изменить — можно только выпустить
  следующую. Это и есть запись истины»*.

### 8. Обмен: DXF
- Панель «Экспорт» → **DXF** → файл + sidecar-манифест скачиваются.
- Открыть DXF в любом стороннем CAD/просмотрщике (nanoCAD, QCAD, онлайн-вьюер):
  стены, проёмы, колонны, объекты — по слоям, размеры в мм.
- Сказать: *«Файл открывается у подрядчика, чем бы он ни пользовался.
  Лицензий не нужно ни нам, ни ему»*.

### 9–10. Клиент согласует
- Под ролью «Заказчик» (приглашение из п. 2) открыть рабочее пространство:
  витрина трёх вариантов — **чертёж**, версия, состав, бюджет в ₽.
- Выбрать вариант, написать причину, «Согласовать».
- Сказать: *«Клиент выбирает по чертежу и цене, решение остаётся в истории
  проекта — вместе с причиной»*.

## Что НЕ показываем (граница A4 держится и в демо)

Фотореалистичный рендер · запись DWG · узлы и конструктивные детали ·
«паритет с ArchiCAD». Если спросят — отвечаем формулой отстройки:
*«Мы не заменяем ваш CAD. Мы помним то, что он забывает»*.

## Быстрая проверка перед показом

`npm run release:check` зелёный · флаг включён · `/dashboard/projects/<id>/layouts`
открывается · экспортированный DXF открыт в стороннем вьюере накануне.
