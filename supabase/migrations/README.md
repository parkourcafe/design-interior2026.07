# Журнал миграций: один исполняемый путь, а не два

**Эта папка — clean-bootstrap-цепочка и только она.** Порядок применения —
лексикографический по имени файла, он же порядок
`tests/ap1/environment/migration-ledger.sha256`, он же порядок, в котором
применяет Supabase CLI. Первый файл —
`20260716071024_legacy_production_baseline.sql`, дальше — additive-цепочка.

Историческая нумерация `0001`–`0009` **в эту папку не входит и входить не
должна**. Её точные байты сохранены как доказательство в
`docs/product-intelligence/agent-runs/db-wave/legacy-migrations/` с расширением
`.sql.txt` — специально нерабочим, чтобы файл нельзя было применить, случайно
подхватив глобом.

## Зачем этот файл написан

Не ради переучёта того, что и так видно в `ls`. Ради того, чтобы следующий
человек не потратил день на уже пройденный тупик.

01.08.2026 Supabase Preview для PR #60 остановился так:

```text
ERROR: legacy production baseline is clean-bootstrap only;
       application relations already exist (SQLSTATE P0001)
```

Тогда `0001`–`0007` лежали здесь же, рядом с baseline. CLI честно применял их
по порядку, а baseline столь же честно отказывался работать поверх уже
созданных legacy-таблиц: он их **заменяет**, а не продолжает. Диагноз занял
отдельный прогон, потому что из содержимого папки этого не следовало никак —
14 файлов подряд выглядели одной цепочкой.

Файлы `0001`–`0007` из исполняемого входа убрали в тот же день
(`AP1_MIGRATION_REPLAY_REPORT_2026-08-01.md`). Но папка так и осталась молчащей:
из неё по-прежнему не следует, почему нумерация начинается с середины,
существовал ли когда-нибудь другой путь и чем он кончился. Молчащая папка —
это приглашение восстановить «недостающие» файлы. Дешевле написать здесь
двадцать строк, чем ловить это ещё раз на Preview.

## Два пути и кому какой

| Куда | Путь | Как |
|---|---|---|
| Чистая база: disposable-стенд, локальный стек, харнессы DB4/DB5, CI | **clean-bootstrap** | `20260716071024_legacy_production_baseline.sql` + вся additive-цепочка в порядке реестра. Единственный исполняемый путь этой папки. |
| Существующий production `ztnycrchwxqczqbyegnp` | **historical incremental** | Ни baseline, ни исторические `0001`–`0007` не применяются. Схема и журнал прода остаются источником истины; изменения — только forward-only additive поверх свежего снапшота. |

Второй путь **не является путём этой папки**. Он описан отдельно и остаётся
закрытым гейтом:

* `AP1_MIGRATION_PATH_DECISION_2026-08-01.md` — направление принято владельцем
  10.08.2026; гейт принятия (снапшот, сверка отпечатка, baseline-adoption SQL,
  журнал replay, постпроверки, откат) **не пройден**;
* `docs/product-intelligence/agent-runs/db-wave/MIGRATION_PATH_DECISION_2026-08-02.md`
  — та же развилка со стороны production compatibility;
* `PLATFORM_FOUNDATION = BLOCKED` держится в том числе этим гейтом.

## Чем поднимать чистую базу

Руками — не надо: у clean-bootstrap есть предусловие, которое из папки не
видно. Роли `pi_table_owner` / `pi_human_executor` / `pi_worker_executor` должны
существовать **до первой миграции слоя**, а `postgres` — иметь их членство с
`inherit true, set true`: в PostgreSQL 16+ роль с `CREATEROLE` получает
`admin_option`, но не `set_option`, и `create schema … authorization` падает с
`must be able to SET ROLE`. Подробности — `AP1_RUNBOOK.md` §2a.

Исполняемый рецепт, закрывающий и это предусловие, и постусловия:

```bash
zsh tests/ap1/environment/bootstrap-disposable.zsh --target local
zsh tests/ap1/environment/bootstrap-disposable.zsh --target hosted
```

Скрипт сверяет хеши реестра до применения, применяет цепочку в порядке
реестра, прогоняет `verify-db.sql` и отказывается работать рядом с production
ref.

## Что здесь нельзя делать

* переименовывать `.sql.txt`-доказательства обратно в `.sql`;
* добавлять файл в эту папку, не обновив `migration-ledger.sha256`: контрактный
  тест `tests/ap1/environment/environment.contract.test.ts` сверяет список и
  хеши побайтово и покраснеет;
* править текст уже применённой timestamped-миграции. Ошибка в тексте —
  запись в `docs/canonical/remhaos-v1/REMHAOS_MIGRATION_ERRATA.md`; ошибка в
  поведении — новая additive-миграция.
