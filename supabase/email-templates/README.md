# Письма входа (Supabase) — как настроить

Два шаблона RemHaOS в этой папке:
- `magic_link.html` — письмо со ссылкой/кодом для входа.
- `confirm_signup.html` — письмо подтверждения при первой регистрации.

Оба показывают **6-значный код** `{{ .Token }}` крупно + кнопку-ссылку `{{ .ConfirmationURL }}`.
Логин уже умеет и то, и другое: можно кликнуть ссылку **или** ввести код на странице входа.

## Часть А — подготовить и проверить шаблоны

В репозиторных `magic_link.html` и `confirm_signup.html` исправлены название
бренда, текст кнопки входа, уведомление о незапрошенной регистрации и примеры
Subject в комментариях: используется **RemHaOS** согласно
[ADR-0005](../../docs/product-intelligence/adr/0005-remhaos-public-brand.md).
Переменные `{{ .Token }}` и `{{ .ConfirmationURL }}`, HTML-структура, цвета и
шрифты сохранены. Для узких экранов ширина внутренней таблицы изменена с
фиксированных 480 px на 92% с ограничением 480 px; HTML-атрибут `width` также
равен `92%` для клиентов, которые используют его вместо inline CSS.
Жёстко заданных ссылок на старый домен в этих шаблонах нет.

Темы для установки: `Вход в RemHaOS — ваш код` и
`Подтвердите вход в RemHaOS`. Комментарий Subject в HTML сам по себе не меняет
тему письма в Supabase.

**Production installation — HOLD.** Исправление файлов репозитория не меняет
установленные шаблоны, Auth settings, SMTP или DNS. Реальная доставка писем,
вход по коду и переход по ссылке остаются **UNVERIFIED**. Перед установкой
нужны проверка обоих писем в почтовых клиентах и token/link flow в разрешённой
disposable-среде, затем отдельный owner gate для применения именно проверенных
шаблонов в production. Локальная подстановка фиктивных значений в HTML не
заменяет эти проверки. Действия части Б выполняются только после такого gate.

### Локальная проверка исправления бренда

- Сравнение с предыдущими шаблонами подтвердило: изменены только брендовый
  текст и ширина внутренней таблицы. Остальные атрибуты и стили, теги и
  переменные Supabase совпадают, HTML сбалансирован.
- Оба письма просмотрены в локальном Chrome с фиктивным кодом `123456` и
  ссылкой на `example.invalid`, без отправки писем и перехода по ссылке.
- При ширинах viewport 320 и 375 px горизонтальное переполнение устранено:
  `scrollWidth` равен соответственно 320 и 375 px у обоих писем (до изменения
  ширины — 488 px). При viewport 600 px внутренняя таблица остаётся шириной
  480 px и центрирована; бренд, код и кнопки отображаются без обрезания.
- Это проверка синтетического HTML в Chrome. Outlook и другие реальные
  почтовые клиенты, доставка писем и настоящий token/link flow не проверены.

## Часть Б — свой SMTP через Resend (для боевой рассылки клиентам)

**Конфигурация проекта:** домен `remhaos.com` (DNS настраивается у текущего
регистратора домена).
Отправитель: `noreply@remhaos.com`, имя `RemHaOS`.

### Шаг 1. Resend: добавить домен
1. **resend.com** → Sign up (можно через Google).
2. Слева **Domains** → **Add Domain** → ввести `remhaos.com` → Add.
3. Resend покажет **3 DNS-записи** (MX/TXT — SPF, TXT — DKIM, TXT — DMARC). Не закрывать эту страницу.

### Шаг 2. Vercel: добавить эти 3 записи в DNS
1. У текущего регистратора домена открыть DNS-записи для **remhaos.com**.
2. Для каждой записи из Resend нажать **Add** и перенести Type / Name / Value.
   - ⚠️ В поле **Name** вписывать только префикс без домена: Resend показывает `send.remhaos.com` → в DNS ввести `send`; `resend._domainkey.remhaos.com` → `resend._domainkey`; `_dmarc.remhaos.com` → `_dmarc`. Для корня — оставить `@`.
   - Значение (Value) копировать целиком, особенно длинный DKIM (`p=...`).
3. Сохранить каждую.

### Шаг 3. Resend: подтвердить
- Вернуться в Resend → на странице домена нажать **Verify DNS Records**. Через несколько минут (иногда до часа) статус станет **Verified**.

### Шаг 4. Resend: создать ключ
- Resend → **API Keys** → **Create API Key** → скопировать `re_…` (показывается один раз).

### Шаг 5. Supabase: включить Custom SMTP
Supabase → production-проект **RemHaOS** → **Project Settings** → **Authentication** → **SMTP Settings** → Enable Custom SMTP:
- Host: `smtp.resend.com`
- Port: `465`
- Username: `resend`
- Password: ключ `re_…`
- Sender email: `noreply@remhaos.com`
- Sender name: `RemHaOS`
- Сохранить → отправить себе тестовое письмо (попробовать войти).
