## Что сделано

- Lifecycle расширен до `proposal_sent → proposal_accepted → active_project`.
- Принятие публичного КП теперь фиксирует не только событие, но и статусы proposal/project.
- Добавлена миграция с минимальными таблицами `project_rooms`, `project_participants`, `project_tasks`, `project_task_events` и RLS для студии-владельца.
- Действие «Создать Project Room из принятого КП» создаёт одну комнату, роли designer/client/executor, стартовые задачи из package/секций КП и до трёх задач из принятых рисков.
- Стартовые задачи связываются с реальными секциями КП (`package`, `works`, `included`, `stages`), а не с несуществующим `scope`.
- Для клиента и исполнителя создаются разные токены доступа. Клиент видит только client-facing задачи; исполнитель — только назначенные ему; дизайнер — всё.
- Изменения статуса задач пишутся в activity log.
- AI-admin MVP детерминированно подсвечивает просроченные, заблокированные, ожидающие клиента и ожидающие исполнителя задачи. Он не меняет статусы и не принимает решений.
- Старые принятия КП, которые были записаны только событиями, backfill-ятся миграцией.

## Как проверить вручную за 5 минут

1. Применить `supabase/migrations/0007_project_rooms.sql`.
2. Отправить КП и на публичной странице нажать «Принять предложение».
3. В кабинете открыть КП: появится действие создания Project Room.
4. Создать комнату и проверить три карточки участников, стартовые задачи и событие создания.
5. Открыть ссылки клиента и исполнителя: клиент не видит internal executor task, исполнитель видит только свою назначенную задачу.
6. Изменить статус задачи в любом разрешённом представлении и проверить activity и AI-admin summary.

## Известные ограничения

- В MVP ровно один client и один executor на комнату.
- Токенные ссылки передаются дизайнером вручную; приглашений и полноценной регистрации участников нет.
- Нет чата, платежей, закупок, vendor discovery, accounting или строительной ERP.
- AI-admin — объяснимые rule-based alerts без LLM-вызова; это намеренно безопасный первый слайс.
- Создание произойдёт только после явного принятия отправленного КП.
