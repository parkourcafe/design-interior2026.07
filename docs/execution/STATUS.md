## Известная поломка механизма — 09.09.2026, требует действия владельца

Первая сессия-оркестратор (`session_0166Fwy6BLVpoohsL5oGFKJ7`) была создана без явного `permission_mode:
"auto"` и унаследовала обычный режим — каждое действие записи (git push, создание PR, создание дочерней
сессии) требовало подтверждения человека, которого не было (будильник по расписанию, без зрителя). Она
простояла ~9 часов, ничего не сделав, сама отменила свою проверку и признала себя нерабочей. Архивирована;
старое расписание (`trig_01BDD88y2A7EAXW51JUWWXxj`) удалено.

Попытка создать замену с явным `permission_mode: "auto"` дала системную ошибку: `create_session` не
может выдать дочерней сессии более permissive режим, чем у создающей её сессии, а создающая (родительская)
сессия владельца в этот момент сама была в режиме `plan`. Это ограничение платформы, обойти его инструментами
нельзя. **Нужно действие владельца:** переключить режим родительской сессии (той, что ведёт этот диалог) на
Auto/Bypass permissions в приложении Claude Code, затем разрешить создание новой сессии-оркестратора. До
этого автономный конвейер не запустится — рабочие пакеты будет ждать своей очереди.

Параметры владельца от 08.09: потолок Claude-сессий $150/неделю, стоп новых рабочих сессий при $120;
модели — ревью `claude-fable-5-1`, рабочие `claude-opus-5`; слияние оркестратором — docs-only и
не-миграционные PR без метки security при зелёном CI и вердикте ревью; миграции, RLS, гранты, security,
