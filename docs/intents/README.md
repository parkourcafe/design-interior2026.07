# Intent layer — RemHaOS (Россия)

Слой намерений пользователя: 28 интентов в 4 сегментах, их приоритеты, связи и разбор пересечений.
Материал для информационной архитектуры и контент-стратегии — **не продуктовый scope v0.1**
(см. `../../CLAUDE.md`, раздел «Что НЕ строить»). Здесь только документы; кода фичи нет.

## Расклад

```
Designer Workflow      9    ├─ 7 в линейной цепочке пресейла, 2 вне её (P2)
Client Education      12    ├─ 8 в пути решения, 4 самостоятельных входа
Studio Management      5    ├─ 3 в цепочке, 2 вне (в т.ч. DESIGNER_007)
Partner Collaboration  2    └─ последовательность не задана
                      ──
                      28    P1: 16 · P2: 10 · P3: 2
```

Три кросс-связи «дизайнер ↔ клиент» — одно событие воронки с двух сторон:
DESIGNER_001 ⇢ CLIENT_010 · DESIGNER_003 ⇢ CLIENT_002 · DESIGNER_004 ⇢ CLIENT_008.

## Итог по дублям

Истинных дублей нет: ни одна пара не совпадает одновременно по формулировке цели, конкурентному
запросу и сегменту аудитории. Единственная пара к слиянию — **DESIGNER_008 + DESIGNER_010**
(один сегмент, одна тема «отслеживание изменений», оба P2, оба high-difficulty).
Подробности и оставшиеся 4 пары — в `intent-duplicates.md`.

## Известные дефекты исходных данных

Эти пункты нужно закрыть до того, как реестр станет источником для автоматизации:

1. **В реестре нет рёбер** — у всех 28 записей `parent_intent: null`, `child_intents: []`.
   Иерархия живёт только в тексте `intent-graph.md`. Генерировать по реестру перелинковку,
   хлебные крошки или sitemap нельзя.
2. **`cannibalization_risk: "Low"` и `confidence: 0.85` одинаковы у всех 28 записей** — поля
   не различают пару DESIGNER_008 / DESIGNER_010 и любой изолированный интент, то есть сейчас
   не несут информации.
3. **Кириллические канонические URL**, один из них с запятой в пути:
   `/узнать,-что-входит-в-дизайн-проект/`.
4. **Расхождение между документами:** отчёт называет Studio Management «5 интентов», но
   перечисляет 4 (пропущен DESIGNER_007). Прав реестр.
5. **Префикс ID не равен сегменту:** DESIGNER_007 относится к кластеру Studio Management
   и `user_segment: "studio"`.

## Что считать актуальным при расхождениях

`intent-duplicates-source.md` рекомендует «оставить всё раздельно» и предлагает объединять
DESIGNER_001 + DESIGNER_009 и DESIGNER_005 + DESIGNER_002. Эти предложения отклонены:
это соседние шаги пресейла с разными целями и разными запросами. Актуальна рекомендация
`intent-duplicates.md` — единственное слияние DESIGNER_008 + DESIGNER_010.
