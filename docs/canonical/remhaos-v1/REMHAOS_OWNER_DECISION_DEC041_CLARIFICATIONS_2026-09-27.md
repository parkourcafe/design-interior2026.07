# OWNER DECISION — уточнения к DEC-041 и нумерация (DEC-043)

Статус: **LOCKED OWNER DECISION**
Дата: 27.09.2026
Основание: ответы владельца в сессии 27.09.2026, после того как была дана оценка
`REMHAOS_OWNER_DECISION_PHASE0_GOVERNANCE_2026-09-27.md` (DEC-041).

## 1. Нумерация

В двух ветках оказалось два разных DEC-040:

- DEC-040 от 23.09.2026 — 90 дней read-only и полного экспорта после окончания
  оплаченного доступа. Остаётся **DEC-040**, DEC-041 ссылается именно на него.
- Решения по финальному аудиту от 25.09.2026 (ветка `claude/phase-0-kg4xd8`)
  получают номер **DEC-042**. Все ссылки в коде, тестах и evidence Фазы 0
  переписаны на DEC-042. Исключение — комментарии в трёх миграциях Фазы 0
  (`20260925090000`, `20260925091000`, `20260925100000`): миграции записаны в
  неизменяемый реестр контрольных сумм
  (`tests/ap1/environment/migration-ledger.sha256`), поэтому их байты не
  меняются, и «DEC-040» в них означает DEC-042. Исторические документы аудита
  (`docs/audits/REMHAOS_FINAL_AUDIT_2026-09-25.md`,
  `docs/audits/REMHAOS_LAUNCH_PLAN_2026-09-25.md`) и старые планы, где
  «DEC-040» означал ещё не принятое решение, не менялись.

## 2. Обязательные merge-проверки (уточнение DEC-041 §1)

В обязательные проверки входят:

- `lint / typecheck / test / build`;
- `DB4 on postgres:16-alpine`, `DB4 on postgres:17-alpine`;
- `DB5 on postgres:16-alpine`, `DB5 on postgres:17-alpine`;
- `AP5 authenticated browser matrix`.

Зачем: защиту Фазы 0 (закрытие `/b/`, права архитектора, гейт M3) доказывают
именно DB4 и DB5. Без них откат защиты мог бы пройти при зелёном CI.

Само включение правила в GitHub — отдельное действие владельца. Этим решением
оно не выполняется.

## 3. Смена chat ID Telegram (уточнение DEC-041 §5.1)

Когда группа становится супергруппой, Telegram меняет её chat ID. В этом случае
привязка чата к Organization/Project/Package переносится **автоматически** по
служебному сигналу Telegram о миграции. Каждый перенос пишется в append-only
аудит: старый ID, новый ID, время и основание.

«Явная аудируемая миграция» означает явный шаг в журнале, а не ручное
подтверждение оператором. Перенос по названию группы, телефону или display name
по-прежнему запрещён.

  DEC-041 §5.3 задаёт только путь quarantine → checksum → scan → review.

## 5. «Единственный активный одобряющий» (DEC-041 §3) — подтверждено 27.09.2026

Формулировка владельца: «Владелец может одобрить паспорт сам только если на
момент решения нет второго **активного** владельца и нет архитектора с
действующей scoped capability на одобрение. Отозванные и неактивные права не
считаются.» Это исключает самоодобрение, когда доступен независимый
уполномоченный проверяющий.

Отзыв права у архитектора не отменяет одобрений, которые он уже выдал: решение
было законным в момент его принятия.

Реализация (`20260927090000`, `_other_passport_approver_count`) считает именно
так: только активные членства в активной организации и только действующее право
`approve_passport`.

Это решение не включает GitHub settings, merge, deploy, production purge,
Telegram production, credentials и external data-plane.
