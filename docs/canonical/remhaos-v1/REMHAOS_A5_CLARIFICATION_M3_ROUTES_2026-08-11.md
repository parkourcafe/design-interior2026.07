# Уточнение к Addendum A5 §4.2.2 — что означает «404 на всех маршрутах модуля»

**Класс документа:** каноническое уточнение к подписанному аддендуму.
**Основание:** OWNER DECISION 11.08.2026.
**Статус:** LOCKED в части §1–§3. §4 — открытый вопрос, требует отдельного решения.
**Запись в журнале:** DEC-028.

---

## 0. Зачем понадобилось

A5 §4.2.2 требует: «флаг модуля M3, выключенный по умолчанию; при выключенном —
**404 на всех маршрутах модуля**». Требование написано по образцу Layout Studio,
у которого есть собственный URL.

У модуля 3 собственного дерева маршрутов нет: он живёт секциями внутри рабочего
пространства проекта. Буквальное исполнение — вернуть 404 на общий workspace —
закрыло бы заодно модуль 2, который на той же странице и открыт.

Первая попытка закрыть это расхождение комментарием в коде
(`documentation-flag.ts`) владельцем отклонена: **комментарий не замещает
требование подписанного документа**. Отсюда настоящее уточнение — оно
и есть форма, в которой требование A5 §4.2.2 действует для M3.

Отдельный маршрут M3 **не создаётся** (решение владельца 11.08).

---

## 1. Общий workspace остаётся `200`

Страница рабочего пространства проекта отвечает `200` при выключенном M3, потому
что содержит модуль 2 — открытый и работающий. Закрыть страницу значило бы
закрыть чужой модуль.

## 2. Встроенные авторские поверхности и данные M3 отсутствуют

При выключенном модуле на этой странице нет ни одной поверхности M3 и ни одной
его записи. Не «скрыты стилями» и не «показаны серым» — отсутствуют в ответе
сервера:

| Что | Как проверяется |
|---|---|
| Команды модуля (`register_source`, `review_source`, листы, `publish_baseline`, `publish_release`) | отклоняются **до первого RPC**; матрица — `lib/project-intelligence/delivery/projectceo/m3-surface.ts` |
| Действия на поверхности | `operations.*` отдают `module_disabled` |
| Данные модуля | `documentation` в проекции равен `null` (`live-read-port.ts`, `documentationView`) |
| Прямой вызов мимо приложения | публикующие RPC отозваны у `authenticated` (`20260811010000`); остаток, закрытый только приложением, назван в матрице |

Это и есть содержание требования A5 §4.2.2 для встроенного модуля: поверхности
модуля не существует для пользователя. Форма — не код ответа страницы, а
отсутствие поверхности и данных.

## 3. Будущие отдельные URL M3 отвечают `404`

Как только у модуля появится собственный URL — страница, маршрут API или любой
другой публичный адрес, принадлежащий только M3, — он обязан отдавать `404` при
выключенном флаге, буквально по A5 §4.2.2 и по образцу Layout Studio. Настоящее
уточнение снимает требование только с **общей** страницы и только пока
собственного адреса нет.

## 4. Открытый вопрос: доступность ранее выпущенных пакетов

**Требует отдельного решения владельца.** Вопрос: если модуль 3 выключен, а
пакеты документации по проекту уже были выпущены раньше, —

* остаются ли они доступны **только для чтения** (просмотр и выгрузка того, что
  уже выпущено), или
* исчезают вместе с поверхностью модуля до его включения?

Аргумент за чтение: выпущенный пакет — обязательство перед получателем, и
выключение модуля у поставщика не должно отзывать уже выданное. Аргумент против:
«модуль выключен» перестаёт быть одним состоянием и становится двумя, а каждое
такое раздвоение раньше приводило к тому, что закрытым считалось не то, что
закрыто на самом деле.

Связано с DEC-026 (срок хранения) и с заменой обещания «вечной читаемости»:
ответ здесь обязан быть согласован с тем, что обещано о сроке.

До решения действует §2 без исключений: при выключенном модуле данных M3 в
ответе нет, включая ранее выпущенные пакеты.
