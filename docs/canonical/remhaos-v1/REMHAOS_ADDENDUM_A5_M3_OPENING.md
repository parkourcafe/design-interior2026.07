## 1. Что открывается

### 1.1 Модуль 3, объём P0 — строго по плану исполнения

Открывается Модуль 3 «Архитектор» (`M3 · Архитектор → Released Production
Package`, AGENTS.md) в объёме ближайшего P0 по
`docs/product-intelligence/wave-3/MASTER_EXECUTION_PLAN.md` §M3:

1. **Intake документации** — PDF, JPG, PNG, CSV, XLSX.
2. **Связи** room / sheet / specification.
3. **Ревизии** документов.
4. **Completeness / conflict review.**
5. **Baseline.**
6. **Immutable Released Production Package** — выход модуля.

Объём взят из плана дословно и **не расширяется толкованием**. Native CAD/BIM
authoring в M3 не строится: авторинг геометрии — территория M2 по A4.

### 1.2 Что остаётся закрытым

- **M4** — закрыт. A4 §1.2 в части M4 продолжает действовать; его открытие
  требует отдельного аддендума. Принятый тонкий P0 M4 из плана этим документом
  **не** авторизуется.
- Всё из раздела «Что не строить сейчас» `AGENTS.md` и §2.1 A4 — без изменений.
- Широкий M2–M4 не размораживается: требование провести через те же contracts
  минимум один внешний реальный пакет остаётся (см. §4.3).

### 1.3 Гибридный M3 — пост-P0, не сейчас

`REMHAOS_M3_IMPACT_NOTE_2026-08-08.md` (в каноническом пакете) описывает M3 как
гибрид: генератор листов из подписанной версии планировки плюс реестр внешних
файлов смежников. Настоящий аддендум фиксирует границу явно, чтобы два
канонических документа не противоречили друг другу молча:

> **Генерация листов из подписанной версии планировки в объём P0 не входит.**
> Она остаётся зафиксированной целью более позднего этапа M3 и требует
> отдельного решения об открытии — по объёму и по сроку.

Записка остаётся действительной как подготовительная (её собственный §6:
«не открывает M3 и не меняет Charter»), и три её обязательства перед M3
продолжают действовать в M2. Первое из них — «`DESIGN_FREEZE` ссылается на
подписанную версию: `versionId` + семантический хеш» — на линии `main`
**уже исполнено**: см. §3.1.

## 2. Вход модуля: единственная дверь

M3 принимает работу M2 **только** как persisted exact handoff —
`publish_m2_m3_handoff` / `createM2ToM3Handoff`
(`lib/project-intelligence/application/m2-to-m3-handoff/index.ts`,
контракт `archidom.m2-to-m3-handoff/0.1`).

Дверь требует: approved commit revision; layout со статусом `published` и
подписью формата `sha256:<hex>`, совпадающей с выбранным вариантом; approved
selection revisions; чистый бюджет (без stale и без missing price).

**Обходов не строится.** Ни чтение таблиц M2 напрямую, ни приём документов без
handoff, ни «временный» путь для отладки. Пакет документации, не привязанный к
exact handoff, не может доказать, по какой геометрии и по каким решениям он
сделан, — а это и есть продаваемое свойство продукта.

## 4. Инварианты M3 — действуют с даты подписи

### 4.1 Из `AGENTS.md` (неподвижные правила платформы)

RLS deny-by-default · human operations без service role · actor / organization /
project / package / role выводятся server-side · published versions, approvals,
releases, handoffs и audit — append-only · идемпотентность повторных запросов ·
строки интерфейса только в `lib/i18n/ru.ts` · деньги — safe integer RUB ·
миграции только additive, каждая — строка в
`tests/ap1/environment/migration-ledger.sha256` (сейчас 28 строк) · AI не
утверждает, не выпускает и не согласовывает автоматически · PII, source text,
оригинальные имена файлов, raw tokens и signed URLs не попадают в логи.

### 4.2 Специфичные для M3

1. **Один движок ревизий.** Ревизии документов M3 ложатся на существующую
   механику версий и revision-контрактов. Второй параллельный механизм не
   строится ни при каких обстоятельствах.
2. **Флаг модуля** M3, выключенный по умолчанию; при выключенном — 404 на всех
   маршрутах модуля. Образец — `ARCHIDOM_LAYOUT_STUDIO_ENABLED`.
3. **Канонизация и подпись** — ADR-001 (кодовые точки Unicode, паритет с
   C-collation) и ADR-0007. Изменение — только новым ADR.
4. **Вечная читаемость** (A4 §5): опубликованный пакет документации и его листы
   открываются и выгружаются вечно в той модели данных, в которой были выпущены.
5. **Публичное имя модуля — «Документация»** (DEC-023 §6). Внутренние имена
   `* Intelligence` и `projectceo_*` наружу не выходят; слово «CAD» в
   самоописании не используется.
6. **Обмен файлами** — строго A4 §3 и `AGENTS.md`: наружу DXF; DWG только на
   сервере и только как подложка; запись DWG, IFC, RVT запрещена; облачная
   конвертация третьей стороной запрещена (152-ФЗ).
7. **Предупреждения** протаскиваются во все артефакты пакета и не снимаются
   молча.

### 4.3 Что подпись A5 НЕ снимает

- **Цикл 7 остаётся открытым и красным намеренно.** `npm run test:cycle7`
  (`vitest.cycle7.config.ts`) не чинится, не удаляется и не объявляется зелёным;
  внешний реальный пакет не предоставлен. Открытие M3 этого требования не
  отменяет — как и ADR-0006 не отменил его при открытии M2.
- **Production adoption** — только отдельным контролируемым решением.
- **Гейты** на каждый слой: `npm run lint · typecheck · test · build`, плюс DB4
  на PostgreSQL 16 и 17 в CI.

## 5. Механический список правок — исполняется тем же коммитом, что и подпись

По образцу A4 §6. Правки затрагивают **оба бренда**; фактическое состояние
зеркала проверено и оговорено отдельно.

| 4 | `docs/canonical/archidom-v1/ARCHIDOM_WORKFLOW_CATALOG_v1.md` | то же для `WF-M3-001` |

| 6 | `AGENTS.md` | добавить строку об открытии M3 по образцу существующей строки про M2/ADR-0006: объём P0, единственная дверь `m2-to-m3-handoff`, цикл 7 остаётся открытым |

Формулировка `Do not build` для M3 объявляется **недействующей с даты подписи
A5** отдельным пунктом, а не следствием: иначе исполнитель, открывший матрицу
вместо устава, будет прав, отказавшись строить (урок A4 §1.3).

**Устав не правится.** §16 «что продукт не делает» документацию не запрещает —
перечень A4 касается CAD/BIM-паритета, который §1.1 настоящего документа
сохраняет. §15 уже относит M3 к P2. Открытие модуля регулируется §20, и
настоящий аддендум — требуемое им решение. ARCHITECTURE §12 (Module 3) не
редактируется по DEC-018 (freeze).

**Расхождение зеркала — зафиксировано, но в A5 не чинится.**
`ARCHIDOM_DECISION_LOG_v1.md` заканчивается на DEC-018: записи DEC-019…DEC-023
в зеркало не переносились (A4 правил в archidom только устав §16). Поэтому
пункт 5 списка касается только remhaos-журнала: дописывать DEC-024 в зеркало
поверх дыры из пяти записей — значит создать видимость синхронности, которой
нет. Синхронизация журнала зеркала — отдельная задача, и она названа здесь,
а не умолчана.

## 6. Условия старта кода M3

Подпись открывает модуль, но код начинается только при выполненных условиях:

1. **A5 подписан** и механический список §5 исполнен.
2. **Гейты зелёные** на момент старта: `lint · typecheck · test · build`
   (напоминание: `test:cycle7` красный намеренно и в это требование не входит).
3. **Первый коммит модуля** — флаг и каркас маршрутов с 404 при выключенном
   флаге, без функциональности.

До подписи — ни строчки кода M3. Настоящий документ, отчёт о проверке и правки
§5 — единственная разрешённая работа.
