# Записка: что меняется в Модуле 3 после появления CAD в Модуле 2

Дата: 08.08.2026 · Основание: подписанный ADDENDUM A4
Класс документа: **подготовительная записка к будущему аддендуму открытия M3.**
Не решение, не Source of Truth (DEC-017). M3 остаётся закрытым: A4 §1.2 требует
для его открытия отдельного аддендума — на сегодня это следующий свободный
номер, ориентировочно A5. Записка существует, чтобы границы этого аддендума
не пришлось изобретать с нуля, а обязательства перед M3 были заложены в M2
заранее, пока это дёшево.

Одобрено владельцем к записи в канонический пакет 08.08.2026 («Да» на
предложение зафиксировать разбор).

## 1. Суть изменения

До A4 Модуль 3 был бы **архивом чужих чертежей**: архитектор чертит во внешнем
CAD, RemHaOS складывает листы, ведёт ревизии, комплектность и выдачу.

После A4 геометрия живёт внутри продукта — подписанные, неизменяемые версии
планировок. Модуль 3 становится наполовину **генератором листов из подписанной
модели**, оставаясь при этом архивом для внешних файлов смежников.

Главный выигрыш — продолжение ниши A4 §2: лист, сгенерированный из подписанной
версии, **доказуемо соответствует модели**. У листа появляется происхождение:
«построен из версии V3, хеш такой-то, утверждена клиентом тогда-то». PDF от
внешнего архитектора такого свойства не имеет и иметь не может.

## 2. По сущностям ТЗ (ARCHITECTURE §12, Module 3)

| Сущность | Без CAD | С CAD (после A4) |
|---|---|---|
| `DrawingSheet` | загруженный PDF | порождается из модели: план, развёртка — производный вид подписанной версии |
| `DrawingRevision` | собственная механика ревизий | переиспользует движок версий M2: неизменяемость, подпись, триггер в БД уже построены |
| `Specification`, `Schedule` | ручные таблицы | производные от модели; ведомость элементов уже есть в печатной форме M2 |
| `TechnicalConflict` | организационная проверка | частично проверка на модели (`clearanceZones` уже в схеме документа) |
| `Transmittal`, комплектность, выдача, `DOCUMENTATION_RELEASE`, `ApprovalStatus` | — | **не меняются** |

## 3. Гибридный режим — обязательная граница будущего аддендума

M3 **не** становится автогенератором рабочей документации. A4 §1.1 запрещает
узлы, конструктивные детали и расчётные разделы: конструктив и инженерка
остаются у смежников и приходят внешними файлами (PDF/DXF).

Следовательно, M3 обязан работать в гибридном режиме: **свои листы из модели +
внешние листы смежников, единый реестр, единая комплектность, единая выдача.**
Комплектность пакета считается по обоим типам листов.

## 4. Три обязательства перед M3, закладываемые в M2 уже сейчас

Это операционная часть записки: дёшево сегодня, дорого потом.

1. **`DESIGN_FREEZE` ссылается на подписанную версию планировки** —
   `versionId` + семантический хеш, а не просто статус. Это соединительный шов
   M2→M3: без него пакет документации не докажет, по какой геометрии сделан.
2. **Один движок версий на оба модуля.** `DrawingRevision` ложится на механику
   версий планировок (неизменяемость + подпись + триггер в БД). Второй,
   параллельный механизм ревизий в M3 не строится ни при каких обстоятельствах.
3. **Поля под ведомости — в шаге «материалы и мебель» M2.** При добавлении
   артикула, поставщика и цены сразу добавляется единица измерения — то, что
   нужно будущим ведомостям M3, а не только расчёту бюджета.

Попутное следствие: **печать в масштабе с рамкой и штампом** (уровень 0
CAD-плана) — де-факто первый `DrawingSheet`. Текущая работа по редактору строит
фундамент M3, не открывая его.

## 5. Конфликт формулировок, который аддендум открытия M3 обязан снять

A4 §1.1 запрещает «спецификации САПР», а сущности M3 в ТЗ — `Specification` и
`Schedule`. Граница, предлагаемая к фиксации:

- **разрешены** ведомости отделки, мебели и проёмов — они фиксируют решения и
  проходят правило обоснования A4 §2.0;
- **запрещены** конструкторские спецификации уровня ГОСТ/BIM — другая
  дисциплина, паритет с САПР.

## 6. Чем эта записка НЕ является

- Не открывает M3 и не меняет Charter, матрицу или каталог.
- Не назначает сроки M3: по действующему плану согласования контуров M3 стоит
  последним, потому что потребляет выход M2, который ещё меняется.
- Не заменяет будущий аддендум — только заготавливает его границы.
