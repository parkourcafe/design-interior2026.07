## 1. Гейты: без чего M3 начинать НЕЛЬЗЯ

Проверяются в первый час новой сессии, по порядку.

1. **Аддендум A5 подписан владельцем.** M3 закрыт подписанным A4 §1.2: «M3 и M4
   остаются закрытыми. Их открытие требует отдельного аддендума». Заготовка
   границ A5 уже написана:
   `docs/canonical/remhaos-v1/REMHAOS_M3_IMPACT_NOTE_2026-08-08.md`.
   Если A5 нет — первая задача сессии: собрать его из записки, дать владельцу
   на подпись, исполнить его §-аналог механических правок (журнал решений,
   матрица, каталог — по образцу A4, см. коммит `a8a70ef`).
   Проверить нумерацию перед подписью: A1–A4 заняты (A2 — Derived Views в
   `docs/brand/`; урок: имя аддендума сверяется с файлами, а не с памятью).
2. **M2 сдан, `DESIGN_FREEZE` существует** и ссылается на подписанную версию
   планировки: `versionId` + `semanticHash`. Это вход M3 по уставу. Если freeze
   реализован просто статусом без ссылки на версию — это дефект M2, вернуть
   туда, в M3 не обходить.
3. **Движок портирован в целевую ветку** (фаза 2 плана согласования контуров)
   и канонический пакет влит. На 08.08.2026 это ещё НЕ так — см. раздел 9.
4. **Гейты кода зелёные**: `npm run lint · typecheck · test · build`.

## 3. Архитектура M3 после A4 — что изменилось

A4 (подписан 08.08.2026) ввёл в M2 собственный геометрический редактор.
Следствие для M3 — смена природы модуля:

**Было бы:** архив чужих чертежей. Архитектор чертит во внешнем CAD, RemHaOS
хранит листы, ревизии, комплектность, выдачу.

**Стало:** гибрид из двух равноправных половин.

1. **Генератор листов из модели.** План, развёртка, ведомость — производные
   виды подписанной версии планировки. У листа есть происхождение: «построен
   из версии V3, хеш такой-то, утверждена клиентом тогда-то». Это продолжение
   ниши A4 §2 (доказуемая история решений) и главный козырь M3.
2. **Реестр внешних файлов смежников.** Конструктив и инженерка приходят
   PDF/DXF извне — A4 §1.1 запрещает строить узлы и расчётные разделы.
   Комплектность и выдача считаются по ОБОИМ типам листов в едином реестре.

Граница по спецификациям (обязательна к фиксации в A5): ведомости отделки,
мебели и проёмов — да (фиксируют решения, правило A4 §2.0); конструкторские
спецификации уровня ГОСТ/BIM — нет (запрещённый паритет).

## 5. Чего нет совсем — это и есть работа M3

- `DrawingSet` — пакет как сущность;
- `Transmittal` — выдача: кому, когда, что, в каком составе;
- комплектность пакета («не хватает развёртки кухни») — по модельным И внешним листам;
- гейт `DOCUMENTATION_RELEASE` и `ApprovalStatus` пакета;
- листы в масштабе 1:50/1:100 с рамкой и штампом (печатная форма M2 — сводка, не чертёжный лист);
- реестр внешних файлов смежников с версиями;
- `DocumentIssue`, `ChangeImpact` в применении к пакету.

## 6. План строительства M3 — порядок и обоснование

Каждый этап проходит правило A4 §2.0 (функция обосновывается фиксацией
решения, не наличием в ArchiCAD) и заканчивается работающим инструментом.

- **Этап 0 · A5.** Собрать из impact-записки, подписать, исполнить механику.
- **Этап 1 · Лист из модели.** Печать в масштабе с рамкой и штампом. Возможно,
  уже сделан в M2 (уровень 0 CAD-плана) — проверить, не строить дважды.
  Закрывает ядро `DrawingSheet`.
- **Этап 2 · Пакет и комплектность.** `DrawingSet` = набор листов, каждый —
  либо (versionId+вид+масштаб), либо внешний файл. Чек комплектности.
- **Этап 3 · Внешние файлы смежников.** Загрузка, версии ТЕМ ЖЕ движком
  (см. инвариант ниже), привязка к пакету.
- **Этап 4 · Выдача.** `Transmittal`: состав, получатель, дата, DXF наружу.
- **Этап 5 · `DOCUMENTATION_RELEASE`.** Гейт выпуска: пакет комплектен, листы
  из подписанных версий, предупреждения не блокируют. Переиспользовать
  механику согласований M1 (approval gate), не строить свою.
- **Этап 6 · Конфликты.** Расширение `TechnicalConflict` поверх clearance.

## 7. Технические инварианты — обязательны, история ошибок приложена

1. **Один движок версий.** `DrawingRevision` ложится на механику версий
   планировок. Второй механизм ревизий не строится ни при каких
   обстоятельствах (записка M3, обязательство №2).
2. **RLS — только по образцу `0008_platform_security_hardening`:**
   `private.is_studio_member(owner)` + `for all to authenticated`.
   НЕ `public.is_studio_member(uuid,uuid)` — он отозван из соображений
   безопасности; копирование шаблона из `0006_team` уже дало отказ всех
   проверок на живой базе (см. DB_STORAGE_VERIFICATION).
3. **Миграции строго аддитивные**, timestamped, ни один существующий файл не
   переименовывается и не удаляется. Актуальную цепочку сверять с целевой
   веткой на момент старта, а не с этим документом: цепочки уже расходились
   (архивный PR #67 переписывал историю — потому он и архив).
4. **Роуты — без service role.** Клиент из cookie дизайнера, проверка подписи
   токена через `auth.getClaims()`, не `getUser()`. Чужое = несуществующее = 404.
5. **Канонизация подписи** — ADR-001: кодовые точки, запрет `localeCompare`;
   любое изменение — только новым ADR.
6. **Модель данных** — только через реестр версий схемы; читатели старых
   версий не удаляются никогда (A4 §5).
7. **Флаг модуля** по образцу `ARCHIDOM_LAYOUT_STUDIO_ENABLED`: свой флаг M3,
   выключен по умолчанию, при выключенном — 404 на всех маршрутах.
8. **Строки интерфейса** — только `lib/i18n/ru.ts`; публичный бренд RemHaOS
   (контрактный тест переименования ловит ArchiDom в UI-поверхностях).
9. **Обмен файлами** — A4 §3: наружу DXF; чтение DWG только на сервере и
   только как подложка; запись DWG, IFC, RVT запрещены; облачная конвертация
   третьей стороной запрещена (152-ФЗ); значения с подложки — неподтверждённые
   до явного подтверждения (A4 §3.3), использовать существующий механизм
   `warnings`, не изобретать параллельный.
10. **Предупреждения** протаскиваются во все артефакты пакета — как в M2.
11. **Владение документами**: канонический пакет правит контур-владелец
    документов; параллельные контуры присылают предложения. Урок двух A2.

## 10. Протокол первого часа новой сессии

1. Прочитать: этот файл → impact-записку → A4 → CHARTER §4/§12/§15 →
   ADR-001 → DECISION_LOG (хвост).
2. Выполнить протокол раздела 9 и гейты раздела 1.
3. Свериться с реестром приёмки M2: что из «инвентаря» (раздел 4) дожило до
