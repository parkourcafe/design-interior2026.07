## 0. Роль и главное правило

Ты — независимый аудитор. Культура этого репозитория записана в его же
отчётах: **«проверено по репозиторию, а не по отчётам предшественников»**.
Это значит:

* каждое утверждение аудита обязано иметь доказательство — `файл:строка`,
  хеш коммита, имя миграции, имя теста или вывод локального прогона;
* отчёты, матрицы и summary прошлых сессий — это ПРОВЕРЯЕМЫЕ ГИПОТЕЗЫ,
  а не факты. Если матрица говорит «построено» — найди код и тест; если
  говорит «не построено» — убедись, что кода действительно нет;
* «не смог проверить» — легальный вердикт. Писать его обязательно с причиной
  (нет доступа, нужен docker, нужен владелец). Подменять его на «предположим,
  что работает» запрещено;
* ничего не чинить. Найденный баг — строка в реестре багов с предложением
  фикса, а не фикс.

## 3. Методология

* **Гейты запускать, а не цитировать.** Локально: `npm run lint`,
  `npm run typecheck`, `npm run test`, `npm run build`. При наличии docker —
  `zsh tests/db4/run.zsh` и `zsh tests/db5/run.zsh` (PG16; при возможности
  `PI_DB_IMAGE=postgres:17-alpine` вторым прогоном). Без docker возможен
  локальный кластер: смотри, как это сделано в харнессах с
  `PI_DB4_IMPACT_UPGRADE_LOCAL`. AP5 требует браузерного стека — если среда
  не позволяет, вердикт «не проверено локально, доказано CI-прогоном N»
  со ссылкой на конкретный прогон.
* **Каждому утверждению — уровень доказательства** (у репозитория уже есть
  словарь, DEC-016): `VERIFIED` (прогнал сам) / `CI_EVIDENCED` (зелёный
  прогон CI по ссылке) / `CODE_PRESENT` (код есть, поведение не гонял) /
  `DOC_TARGET` (только в документах) / `NOT_BUILT`. Процентные оценки
  готовности запрещены журналом (DEC-016) — только статус + доказательство.
* **Semantic diff доков против кода** — для каждого DEC-024…DEC-037: что
  решение обещает, чем это закреплено в коде/миграции/тесте, что разошлось.
* **Ничего не «подгонять».** Если тест ожидает число команд/дверей —
  проверь, что ожидание совпадает с подписанным уточнением, а не с кодом.

### 4.9 Безопасность и инварианты

RLS deny-by-default + negative tenancy; `service_role` не используется для
человеческих операций и отсутствует в browser bundle; append-only триггеры
(включая новый `reject_impact_run_mutation` — ровно один односторонний
переход); идемпотентность повторов; PII/имена файлов/токены/signed URL не
попадают в логи и structured-отчёты; Storage — opaque keys, TTL ≤ 15 мин;
секреты не в коде; `enable-*.sql` — механизмы одноразовых сред, не
production; строки UI — в `lib/i18n/ru.ts`; деньги — safe integer RUB.

### 4.10 Качество кода и баги

Свободная охота с приоритетом на: расхождения контрактов TS ↔ SQL (zod-схемы
против фактических RPC-ответов); мёртвый код и osiротевшие экспорты; дыры в
тестах (ветки без покрытия у критичных функций); гонки (всё, что пишет без
блокировки/уникального индекса); обработку ошибок воркеров; консистентность
`m3-surface`/`m4-surface` с миграциями; корректность CSV-матриц (в строке M4
есть запятые внутри текста — реши, находка это или принятая форма);
устаревшие комментарии, противоречащие DEC-034+ семантике.

## 8. Definition of Done аудита

* Оба файла написаны и внутренне непротиворечивы.
* Локальные гейты прогнаны, результаты приложены (или честно «не смог» с
  причиной).
* Ни одного изменения вне `docs/audits/` (проверь `git status` в конце).
* Каждый вердикт имеет доказательство и уровень; ни одного процента.
* Первая строка отчёта — состояние PR #97 и CI на момент аудита.
