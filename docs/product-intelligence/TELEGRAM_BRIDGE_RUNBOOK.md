# Telegram Chat Bridge — операционный runbook

**Класс документа:** Execution / Implementation Report.
**Основание:** Addendum A7 (`REMHAOS_ADDENDUM_A7_TELEGRAM_CHAT_BRIDGE.md`), DEC-031.
**Область:** local, CI и **закрытый staging с тестовыми участниками**.

> **PRODUCTION ЗАПРЕЩЁН.** A7 §9 не разрешает production-включение вовсе — до
> закрытия legal / data-plane / consent / retention гейта и отдельного OWNER GO.
> Ни один шаг этого документа не исполняется в рабочем окружении.

---

## 0. Что должно быть на руках

| Что | Откуда | Куда |
|---|---|---|
| Токен тестового бота | `@BotFather` → `/newbot` | `TELEGRAM_TEST_BOT_TOKEN` |
| Username тестового бота | оттуда же | `TELEGRAM_TEST_BOT_USERNAME` |
| Секрет вебхука | `openssl rand -base64 48` | `TELEGRAM_TEST_WEBHOOK_SECRET` |
| Приватная тестовая группа | создаётся человеком в Telegram | — |
| ID тестовой группы (для диагностики) | см. §6 | `TELEGRAM_TEST_CHAT_ID` |

**Секреты не коммитятся.** Токен бота и секрет вебхука не попадают в базу и не
пишутся в логи: колонок под них в схеме нет, а диагностика фильтрует всё, что не
идентификатор, код или число.

Бот **обязан** остаться с включённым privacy mode глобально
(`@BotFather` → `/setprivacy` → `Enable`). Полный приём существует только там,
где пользователь сам сделал бота администратором **проектной** группы.

## 1. Включение в одноразовой среде

Границ у запрета две, и снимать надо обе.

```bash
# 1. Приложение.
export REMHAOS_TELEGRAM_BRIDGE_ENABLED=true

# 2. База: человеческий контур. Системный этим НЕ открывается и не может быть
#    открыт — его RPC выданы только service_role.
psql "${SUPABASE_DB_URL}" -X --set ON_ERROR_STOP=1 \
  -f tests/ap1/environment/enable-telegram-bridge.sql
```

Скрипт падает с `REMHAOS_TELEGRAM_BRIDGE_SYSTEM_PATH_LEAKED`, если системный
контур окажется доступен человеческой сессии. Это не перестраховка: одна лишняя
строка в его `grant` означала бы, что кто угодно может сфабриковать входящее
сообщение чужого проекта.

**Откат:** повторно применить `revoke` из миграции `20260811050000` и снять
переменную окружения. `revoke` идемпотентен.

## 2. Установка вебхука

Вебхук ставится **один раз на бота** и указывает на один экземпляр приложения.
Два стенда с одним ботом невозможны: Telegram хранит ровно один URL.

```bash
curl -sS -X POST "https://api.telegram.org/bot${TELEGRAM_TEST_BOT_TOKEN}/setWebhook" \
  -H 'content-type: application/json' \
  -d @- <<JSON
{
  "url": "https://<хост-стенда>/api/integrations/telegram/webhook",
  "secret_token": "${TELEGRAM_TEST_WEBHOOK_SECRET}",
  "allowed_updates": ["message","edited_message","my_chat_member","chat_member","callback_query"],
  "drop_pending_updates": true
}
JSON
```

`drop_pending_updates: true` — не оптимизация. История до подключения не
импортируется (A7 §5.3), и вываливать накопленное на свежую привязку значило бы
нарушить это обещание в первую же секунду.

URL обязан быть HTTPS: Telegram не поставит вебхук на HTTP.

Проверка:

```bash
curl -sS "https://api.telegram.org/bot${TELEGRAM_TEST_BOT_TOKEN}/getWebhookInfo" \
  | jq '{url, has_custom_certificate, pending_update_count, last_error_message}'
```

`last_error_message` — первое, что стоит смотреть при тишине.

## 3. Подключение чата к проекту

Порядок жёсткий, и каждый шаг делает человек.

1. **Настройки проекта** → `/dashboard/projectceo/projects/<projectId>/integrations`.
   Экран доступен только тому, у кого есть `manage_project_integrations` —
   в P0 это владелец проекта. Остальным маршрут отвечает `404`.
2. **«Связать мой Telegram-аккаунт»** — откроется приватный чат бота с
   одноразовым `?start=<token>`. Связь строится по числовому Telegram user ID;
   username может меняться сколько угодно.
3. **«Создать или подключить Telegram-чат»** — Telegram сам предложит
   **создать новую группу или выбрать существующую** и добавит туда бота.
   *Бот не может создать группу за человека, и интерфейс этого не обещает.*
4. **Сделать бота администратором группы** с минимально необходимыми правами.
   Без этого он не увидит переписку — privacy mode включён глобально.
5. Бот публикует **уведомление участникам**. Только после него начинается полный
   приём. Если сообщение не ушло, приём не открывается: следующее событие в этом
   чате повторит попытку.

Токен подключения живёт **10 минут** и срабатывает **один раз**. Истёкший,
использованный и выдуманный токен дают один и тот же отказ.

**Одно уведомление не закрывает 152-ФЗ.** Это продуктовая честность, а не
юридическое основание — см. A7 §5.3 и §9.

## 4. Запуск исходящей очереди

```bash
npm run worker:telegram-outbox
```

Один проход: догоняющий проектор превращает выдачи выпуска без уведомления в
строки outbox, затем очередь берётся в аренду и отправляется.

При выключенном мосте воркер завершается успешно и **ничего не делает** — ни
чтения очереди, ни отправки (`worker_noop`).

Гарантия — **at-least-once + внутренняя дедупликация**. Telegram `sendMessage` не
принимает внешнего ключа идемпотентности, поэтому exactly-once не обещается:
после неопределённого сетевого результата редкий повтор уведомления допустим.
Повтор бизнес-действия — нет, и он закрыт идемпотентностью командных RPC.

Периодичность в staging — по месту (cron, ручной запуск). Чем запускать воркер в
production, решается **вместе с** production-включением, и до него не решается
вовсе.

## 5. Остановка

По возрастанию радиуса:

| Что нужно | Как |
|---|---|
| Отключить один чат | Настройки проекта → «Отключить чат». Привязка отзывается, неотправленные уведомления отменяются той же транзакцией |
| Остановить приём у всех | `REMHAOS_TELEGRAM_BRIDGE_ENABLED=false` + рестарт. Вебхук ответит `404`, Telegram перестанет доставлять |
| Полный kill switch | `deleteWebhook` у Telegram **и** повторный `revoke` из `20260811050000`. Обе границы закрыты, включая прямой вызов через Data API |

```bash
curl -sS -X POST "https://api.telegram.org/bot${TELEGRAM_TEST_BOT_TOKEN}/deleteWebhook"
```

Отключение **не удаляет** привязку — оно её отзывает. История подключения часть
аудита: стереть её значит потерять ответ на вопрос «кто и когда открыл канал».

## 6. Ротация секретов

**Секрет вебхука** — без простоя:

1. сгенерировать новый;
2. выкатить приложение с новым значением;
3. `setWebhook` с тем же URL и новым `secret_token`.

Между шагами 2 и 3 Telegram будет слать старый заголовок и получать `401`. Он
повторит — сообщения не потеряются, приём восстановится сам.

**Токен бота** (`/revoke` у `@BotFather`) — со простоем: старый токен умирает
мгновенно, вебхук слетает. После ротации `setWebhook` обязателен.

Ни один из них не хранится в базе и не пишется в логи. `getFile` возвращает
относительный путь; download URL содержит токен и не собирается нигде, кроме
места скачивания.

## 7. Диагностика

Все события моста — одна строка JSON с `"channel":"telegram"`. В них **нет** ни
текста переписки, ни имени файла, ни токена, ни секрета, ни download URL, ни
внешних идентификаторов чата и участников: значения, не прошедшие фильтр,
отбрасываются целиком.

| Симптом | Где смотреть | Обычная причина |
|---|---|---|
| Тишина в чате | `getWebhookInfo` → `last_error_message` | вебхук не поставлен, HTTPS-сертификат, приложение недоступно |
| `webhook_rejected` c `bridge_disabled` | env стенда | мост выключен |
| `webhook_rejected` c `secret_mismatch` | env и `setWebhook` | секреты разошлись после ротации |
| `webhook_dead_letter` c `chat_not_bound` | настройки проекта | бота добавили в постороннюю группу — содержимое не сохраняется, и это правильно |
| `webhook_dead_letter` c `capture_not_active` | статус привязки | уведомление участникам не опубликовано либо бота понизили |
| `binding_suspended` c `bot_membership_lost` | права бота в группе | бота удалили или понизили; вернуть админа, следующее событие откроет приём |
| `notification_retry` c `rate_limited` | — | Telegram назвал срок; воркер соблюдает его ровно |
| `notification_failed` | `attempts` в событии | исчерпан потолок попыток → dead letter |
| Уведомлений нет вовсе | активная привязка проекта | проектор молчит, если у проекта нет активной привязки |

**Повторная обработка.** Уведомление в `failed` и событие в `dead_letter`
воркером больше не берутся — это сознательно: вечный круг хуже потери, он ещё и
скрывает её за шумом. Возврат в работу — операционное действие по строке
(`status='pending'`, `next_attempt_at=now()`), и делать его надо, зная причину, а
не «на всякий случай».

**Что нельзя починить перезапуском.** Вложения приходят со статусом
`materialization_blocked`: общий карантинный конвейер для этого источника ещё не
доказан, байты не скачиваются. Это не сбой и не чинится ретраем — это названный
остаток, и до него отдельная работа.

---

## 8. Чего этот runbook не делает

Не включает production. Не открывает M4 Increment 2. Не заводит второй бот на
модуль. Не импортирует историю переписки. Не обещает синхронизацию удалений:
обычный бот не получает надёжных событий обо всех удалённых сообщениях.
