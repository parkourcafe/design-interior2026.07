# Pilot pack

Материалы подготовлены заранее; проведение интервью, получение согласия и продажа пилота остаются человеческой работой.

## 1. Общий формат concierge pilot

Длительность: один живой проект или 2–4 недели. В пилоте проверяется не количество сгенерированных документов, а повторяемая цепочка:

```text
реальные источники
→ найденные пропуски/решения
→ human confirmation
→ handoff
→ одно реальное изменение
→ проверенный impact list
```

Обязательные артефакты:

- baseline времени текущего процесса;
- исходные документы с разрешением на обработку;
- журнал действий до/после;
- список ошибок/пропусков, найденных человеком и системой;
- оценка каждого impact: correct / missing / false positive;
- решение о втором живом проекте.

Не считать успехом регистрацию, комплимент продукту или просмотр демо.

## 2. ArchiDom Studio Edition — US

### Recruitment message

> We are testing a focused project-intelligence workflow for principal-led residential interior design firms. It turns questionnaires, calls, plans and references into a sourced project brief, scope/risk review and production handoff, then shows what needs review when a client decision changes. We are looking for firms willing to run one real project with us in a paid concierge pilot. This is not a CRM, CAD tool or procurement replacement.

### Qualification

- full-service residential interiors;
- 3–12 people or comparable principal-led operating model;
- active renovation/whole-home project;
- current workflow uses multiple documents/tools;
- founder/principal can approve pilot;
- senior designer/PM can work with the product weekly;
- willingness to provide a second project if the first succeeds.

### Discovery questions

1. Walk through the last project from first client input to approved scope. Show the actual artifacts.
2. Where did information get retyped, summarized or lost?
3. Which omissions were discovered after the proposal or after production started?
4. How are assumptions distinguished from confirmed client decisions?
5. Show the last meaningful client change. Who had to update what?
6. How was scope/fee impact communicated and approved?
7. Which system is trusted for rooms, decisions, schedules and revisions?
8. What would make a generated brief unsafe to use?
9. What result would justify paying for the pilot?
10. If the pilot works, which second live project would you run?

### Pilot offer hypothesis

- one real project;
- assisted ingestion and setup;
- source-linked project passport;
- scope/risk/assumption review;
- proposal/handoff package;
- one tracked change-impact exercise;
- price test: `$300–1,000`, negotiated as research pricing rather than a published plan.

## 3. ProUp Renovation — Россия

### Сообщение для рекрутинга

> Мы тестируем не ещё одну ERP и не 3D-планировщик, а узкий переход из утверждённого дизайн-проекта в управляемое исполнение. На одном реальном объекте проверим комплектность пакета, свяжем помещения, решения, работы и материалы, а затем покажем последствия одного изменения по стоимости, сроку и заданиям.

### Квалификация

- дизайн+ремонт студия или ремонтная компания 3–20 человек;
- есть утверждённый или близкий к утверждению дизайн-пакет;
- есть ответственный руководитель проекта/прораб/комплектатор;
- компания ведёт несколько объектов, а не один личный ремонт;
- готовность показать фактические документы и последствия изменений;
- возможен второй объект при доказанном результате.

### Discovery-вопросы

1. Покажите последний пакет, который пришёл в производство. Что вы проверяли вручную?
2. Какие пропуски или конфликты обнаружились уже после выхода бригады?
3. Как помещение связано с работами, материалами, закупками и ответственными?
4. Где фиксируется утверждённая замена материала?
5. Покажите последнее изменение стоимости или срока: кто инициировал и кто согласовал?
6. Как отличить актуальный лист/ведомость от устаревшего?
7. Где теряются решения между дизайнером, прорабом, комплектатором и заказчиком?
8. Какие документы обязательны на старте, этапе и сдаче?
9. Как измерить предотвращённую переделку?
10. Какой второй объект вы дадите продукту при успешном пилоте?

## 4. Data request checklist

Запрашивать минимально необходимое и только после согласия:

- questionnaire/brief;
- email or transcript sample;
- plans/specifications;
- room list;
- scope/proposal or estimate;
- one known decision change;
- resulting revised artifacts;
- timestamps or rough labor time;
- список участников по ролям без лишних персональных данных.

Перед передачей:

- определить data region;
- согласовать retention/deletion date;
- удалить лишние PII и секреты;
- зафиксировать, какие AI-провайдеры могут получить содержимое;
- запретить использование данных другого клиента как demo fixture.

## 5. Pilot scorecard

Оценка 0/1 по каждому пункту:

- доступен реальный проект;
- pilot оплачен;
- baseline измерен;
- source provenance проверен;
- хотя бы один существенный пропуск найден до следующей стадии;
- реальное изменение прошло через impact;
- пользователь признал impact list полезным;
- handoff реально использован downstream;
- клиент готов повторить workflow;
- назван второй живой проект.

Гейт продолжения: обязательны `pilot оплачен`, `handoff использован` и `второй живой проект`; суммарный score — не ниже 7/10.

## 6. Post-pilot debrief

1. Какое решение продукт помог принять быстрее или безопаснее?
2. Где результату нельзя было доверять и почему?
3. Что пришлось всё равно переносить вручную?
4. Какие impacts были лишними, а какие пропущены?
5. Кто получил основную ценность и кто должен платить?
6. Что исчезнет из текущего процесса, если продукт останется?
7. Запускаем ли второй проект сейчас? Если нет — какое точное условие не выполнено?
