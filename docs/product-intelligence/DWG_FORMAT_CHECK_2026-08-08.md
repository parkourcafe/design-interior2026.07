## Результат: версии формата

```text
23 файла  AC1021   AutoCAD 2007–2009
 3 файла  AC1032   AutoCAD 2018+
```

`AC1032` — у `A01-301 Tenants`, `A01-308 Tenants`,
`A02-101 AC Room Details - Canopy Glass`. Остальное — `AC1021`.

**`AC1037` не встречается ни разу.** Опасение из §3.2 о том, что современный
AutoCAD пишет формат новее читаемого бесплатными библиотеками, на этом пакете
не подтвердилось. Обе найденные версии входят в диапазон, который заявляет
LibreDWG (до R2018 включительно).

**Вывод по пункту 1: вариант B не заблокирован форматом.** Откат на вариант A
по этому основанию не требуется.

## Дополнение 09.08.2026: разбор живого файла выполнен

LibreDWG 0.13.3 собрана из release-исходников (`--disable-bindings`) в среде
проверки. Прогнаны все 26 файлов.

**Продуктовый путь — `dwgread --format json` — читает 26 из 26.** Целевой
`A01-201 First Floor Layout.dwg` (`AC1021`): exit 0, `SUCCESS`, **7775
объектов** — 3728 `LINE`, 563 `INSERT`, 536 `LWPOLYLINE`, 280 `SPLINE`,
211 `MTEXT`. Для подложки это полная геометрия плюс подписи.

Опасение о слабой поддержке R2007 на этом корпусе не подтвердилось для чтения.
**Пункт «разбор живого файла» закрыт.**

Три находки, каждая — известное ограничение, не блокер:

1. **`dwg2dxf` (писатель DXF) обрывается на 12/26 файлах R2007** после секции
   BLOCKS — без `ENTITIES` и `EOF`; строгий `ezdxf` такие файлы отвергает.
   Чтение тех же файлов через JSON при этом полное — дефект в писателе, не в
   читателе. Следствие для реализации: **подложку строить на `dwgread`/JSON
   (или API библиотеки), не через `dwg2dxf`**. Исходящий DXF продукт и так
   пишет сам (`ezdxf`, MIT) — обрывочный писатель LibreDWG нигде не нужен.
2. **Не-UTF8 байты в текстовых полях JSON** у 11/26 файлов (исходные кодировки
   CAD-текстов). Лечится толерантной декодировкой (`errors="replace"` или
   определение кодировки); в худшем случае — кракозябры в отдельных подписях
   подложки, геометрия не затронута.
3. **~300 `UNKNOWN_OBJ`** в целевом файле — проприетарные объекты, которые
   библиотека не понимает. Для подложки допустимо по определению: пятно видно
   глазом.

## Что осталось по §3.2

**Обратное направление**: DXF, записанный нашим продуктом, должен открыться в
настоящем CAD подрядчика (ArchiCAD/AutoCAD) — слои, блоки, тексты, размеры.
Требует реального CAD, в среде проверки его нет. И **кириллица**: в этом
корпусе её нет (проект индонезийский), проверка переносится на первый
русскоязычный пакет.

Реализация подложки разблокирована.

## Побочное наблюдение

Пакет состоит из отдельных чертежей по дисциплинам с осмысленной нумерацией
(`A01-201`, `E04-101`, `P02-100`), рядом с каждым лежит `.bak`. Это обычная
рабочая практика подрядчика. Для подложки это означает, что дизайнер будет
выбирать конкретный лист из десятков, а не «загружать проект» — сценарий выбора
листа надо предусмотреть в интерфейсе с самого начала.
