# ADR-0008: Один RemHaOS, изолированные региональные data cells

- Статус: принято владельцем
- Дата: 11.09.2026
- Основание: владелец поручил начать реализацию варианта B из
  `RU_US_MARKET_PLAN_2026-09-11.md`.
- Заменяет: запрет на multi-region runtime в ADR-0004 и разделах архитектуры,
  где второй регион оставлен только будущей возможностью.

## Решение

RemHaOS остаётся одним публичным продуктом и одной кодовой базой. Runtime
собирается из двух изолированных региональных ячеек:

- `ru` — первичный сбор и хранение данных российского контура;
- `us` — первый международный контур для США.

Пользовательское market-значение `international` маршрутизируется в физическую
cell `us`. Такое разделение сохраняет существующий frozen schema contract
`deployment_cells.cell_code in ('us', 'ru')` и не превращает выбор рынка в
юридическое утверждение о пользователе.

Региональная ячейка назначается до первого сбора пользовательских данных.
Явный выбор пользователя хранится как основание маршрутизации. Российские
сигналы могут консервативно повысить маршрут до `ru`, но не могут незаметно
перевести пользователя из `ru` в `international`. При отсутствии достаточного
основания используется `ru`. Аудит хранит категорию доверенного сигнала и
причину результата без сырого IP, телефона или locale в routing basis.

Market — операционный proxy маршрутизации, а не доказательство гражданства,
налогового резидентства или применимого права.

Каждый проект, его content, storage, audit, logs и backups принадлежат ровно
одной data cell. Между cells общими остаются исходный код, версии схем,
обезличенные шаблоны и совместимые идентификаторы типов. Межрегиональное
копирование персональных данных не выполняется автоматически.

AI policy определяется той же server-derived cell. Для `ru` разрешаются только
утверждённые российские провайдеры; международная cell использует собственный
allowlist. До отдельного решения этот международный allowlist пуст и AI-вызовы
fail closed. Клиент не передаёт имя data cell или AI provider как источник истины.

Data cell не определяет валюту, язык интерфейса, договорную сторону или набор
юридических документов. Эти параметры выводятся из отдельных утверждённых
commercial/legal contracts; значение `international` само по себе не означает США.

## Поэтапное внедрение

1. Чистый контракт market/cell и fail-closed policy без сетевых подключений.
2. Request-bound фиксация назначения рынка и неизменяемая привязка проекта.
3. Вторая конфигурация Auth/DB/Storage и её disposable verification.
4. Маршрутизация AI, storage и фоновых задач по server-derived cell.
5. Отдельная активация каждой cell после legal/data-plane/production gates.

## Инварианты

- один бренд RemHaOS и четыре рабочие области M1–M4;
- internal `projectceo` namespaces не переименовываются;
- неизвестный или некорректный market не попадает в international;
- проект нельзя переместить между cells обычным update;
- cookies, Auth session и request context не смешиваются между cells;
- отсутствие конфигурации выбранной cell блокирует операцию;
- feature flag не является доказательством data residency;
- provider, storage и DB выбираются server-side из одной cell policy.

## Не разрешено этим ADR

- применение миграций к shared/production DB;
- создание или оплата облачного проекта;
- перенос существующих пользователей и проектов;
- включение production routing, DNS, credentials или deployment flags;
- утверждение юридических текстов, уведомлений или трансграничных оснований.
