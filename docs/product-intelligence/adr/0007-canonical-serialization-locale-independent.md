# ADR-0007: Канонизация Layout Document — по кодовым точкам, замерзает при первой публикации

Статус: **accepted**. Дата: 8 августа 2026 года.
Основание: A2 §5 (вечная читаемость опубликованных версий) и exact-version
контракт M2 (подпись версии — привязка для согласований и передачи в M3).

## Контекст

Подпись версии планировки — SHA-256 от канонической сериализации документа
(`lib/layout-studio/domain/canonical.ts`). Две реализации разошлись:

- **M2** (`codex/archidom-m2-p0-integration`): сущности сортируются сравнением
  по кодовым точкам Unicode (`compareUnicodeCodePoints`);
- **ветка движка** (`feat/layout-studio-engine`): сортировка заменена на
  `a.id.localeCompare(b.id)`.

`localeCompare` без явной локали зависит от ICU и настроек процесса: один и тот
же документ даёт разные сериализации — и разные подписи — на разных машинах.

Это не только межмашинная недетерминированность. Выбор кодовых точек в M2 —
**паритет с базой данных**: PostgreSQL с C-collation сортирует так же, и тест
`tests/layout-studio/domain/canonical-parity.test.ts` (LS-011) прямо ссылается
на контракт `sql-c-collation-parity`. `localeCompare` гарантированно расходится
не только между машинами, но и с сервером, который проверяет те же подписи.

На ветке движка тест LS-011 отсутствует — страховка снята в том же изменении,
которое сломало сортировку. Это не упрёк, а иллюстрация: без письменного правила
расхождение воспроизведётся снова.

## Решение

1. **Каноническая сортировка — сравнение по кодовым точкам Unicode.** Эталон —
   реализация M2. При слиянии ветка движка принимает её без изменений.
2. **Локале-чувствительные сравнения в пути канонизации запрещены**:
   `localeCompare`, `Intl.Collator` и любые API, чей результат зависит от
   локали процесса.
3. **Алгоритм канонизации и вычисления подписи замерзает в момент первой
   реальной публикации.** После неё изменения возможны только новой версией
   схемы документа, с бессрочно сохраняемыми читателями прошлых версий (A2 §5).
   Сейчас реальных публикаций нет — цикл 7 не прогонялся; окно для этого
   решения открыто и закрывается первым боевым прогоном.
4. **Тест LS-011 обязателен и не подлежит удалению.** Дополнительно статический
   тест (`canonical-locale-pin.test.ts`) не пропускает локале-чувствительные
   сравнения в файлы канонизации по имени.

## Последствия

- Слияние движка обязано взять `canonical.ts` из M2 и вернуть LS-011.
- Строгие типы движка (`kind`-юнионы, `rotationDeg: 0|90|180|270`) этим ADR не
  затрагиваются и принимаются отдельно — они меняют валидацию, не сериализацию.
- Любой будущий рефакторинг канонизации до первой публикации допустим только
  при неизменности выхода `canonicalSerialize` на векторах LS-011.
