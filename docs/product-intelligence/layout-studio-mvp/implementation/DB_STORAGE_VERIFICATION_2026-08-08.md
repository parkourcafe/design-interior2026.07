Миграция: `supabase/migrations/20260808050000_layout_studio_documents.sql`
Проверено на: PostgreSQL 16.13, одноразовый локальный кластер. Production не
затрагивался.

## Как проверялось

Не чтением глазами. Поднят чистый кластер, засеяны роли и схемы, которые
Supabase создаёт до миграций (`anon`, `authenticated`, `service_role`,
`auth.uid()`, `auth.users`, `storage.buckets`), затем **все 20 миграций
накатаны по порядку имён** — 19 существующих и новая последней. Все прошли.

Затем заведены два независимых дизайнера со своими проектами, и поведение
проверено от лица роли `authenticated` с разными `auth.uid()`.

## Найденная и исправленная ошибка

Первая версия миграции копировала шаблон RLS из `0006_team.sql`:

```sql
using (public.is_studio_member(designer_id, auth.uid()))
```

Живая база сразу вернула `permission denied for function is_studio_member` на
**всех восьми** проверках. Причина: миграция `0008_platform_security_hardening`
специально отозвала `public.is_studio_member(uuid, uuid)` у роли
`authenticated` — функция была доступна через публичный Data API — и заменила
все политики на `private.is_studio_member(owner)` с явным `to authenticated`.

То есть шаблон, который я взял, был не «старым», а **отменённым по соображениям
безопасности**. Миграция переписана на актуальный шаблон. Тест
`tests/layout-studio/integration/integration.test.ts` теперь статически ловит
возврат к дореформенному варианту: он падает, если в файле миграции появится
вызов `public.is_studio_member(`, если у любой из трёх таблиц не включён RLS,
если политика не ограничена ролью `authenticated`, или если исчезнет триггер
неизменяемости.

Эту ошибку не поймали бы ни линтер, ни типы, ни сборка. Её поймал только
реальный прогон.

## Что появилось в схеме

Три таблицы, все с RLS, все привязаны к проекту и через него — к студии:

- `layout_documents` — текущий черновик планировки, одна строка на планировку;
  `document_id` глобально уникален, потому что движок адресует документ только
  по нему;
- `layout_checkpoints` — именованные снимки, защищены триггером от изменения;
- `layout_versions` — опубликованные версии с семантическим хешем, защищены
  триггером от изменения и удаления.

Каскад `on delete cascade` от `projects`: удаление проекта уносит его
планировки.

## Аддитивность

Ни один существующий файл миграции не тронут: было 19, стало 20. Проверка
`adds migrations only additively` в `integration.test.ts` падает, если хоть один
из 19 исчезнет или будет переименован — тот самый сценарий, из-за которого
нельзя мержить ветку `codex/archidom-layout-studio-m2`.

## Что этой миграцией ещё НЕ сделано

Схема готова, но кода, который в неё пишет, пока нет. Дальше по плану:
серверная реализация хранилища с теми же девятью методами, что у
`MemoryLayoutRepository`, и перевод редактора с `localStorage` на неё.
До этого момента модуль остаётся выключенным.
