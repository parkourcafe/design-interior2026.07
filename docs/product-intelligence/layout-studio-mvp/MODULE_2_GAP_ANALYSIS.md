## Что ТЗ говорит про Модуль 2

**CHARTER §4.** M2 · Дизайнер. Вход: утверждённая основа проекта. Выход:
утверждённый Design Intent и `DESIGN_FREEZE`. — Формулировка владельца «после
утверждённого КП» совпадает с ТЗ по смыслу. Место выбрано верно.

**ARCHITECTURE §12.** Module 2 — Design Intelligence: паспорт → концепции →
варианты → материалы → мебель → бюджет → согласование. Сущности:
`DesignConcept`, `ConceptOption`, `MaterialSelection`, `FurnitureSelection`,
`RoomDecision`, `DesignConstraint`, `ClientFeedback`, `ConceptApproval`,
`BudgetImpact`.

Ни стен, ни узлов, ни проёмов в списке нет. **Модуль 2 по ТЗ — про решения и их
согласование, а не про черчение.**

**WORKFLOW CATALOG · WF-M2-001** «Passport to Design Freeze»:
`CATALOG_ONLY / NOT AUTHORIZED FOR SPRINT 1`.

## Три гейта, которые сейчас закрывают M2

1. **CHARTER §20 (Architecture Freeze).** «M2–M4 не открываются широко до
   доказанного полного пилотного среза или отдельного OWNER DECISION.»
   Здесь же и выход — отдельное решение владельца.
2. **READINESS MATRIX.** Строка: `M2, Design workflow, NOT_PROVEN, DOC_TARGET,

## Прямое ограничение: §16

CHARTER §16, «что продукт не делает»: **не CAD/BIM/3D редактор**.

Построены 2D-план, 3D-вид и рисование стен мышью. Ещё два шага в ту же сторону —
и это буквально CAD, который устав запрещает. Обходить эту строку нельзя.

Противоречие снимается формулировкой границы, а не софистикой. §1 говорит, что
продукт продаёт «управляемость решений, повторяемые процессы и доказуемое
состояние проекта». У редактора есть то, чего нет у CAD: неизменяемые версии с
семантическим хешем, предупреждения о непроверенных данных во всех выгрузках,
запрет подмены задним числом на уровне БД.

**Предлагаемая граница:** не «CAD внутри RemHaOS», а **поверхность фиксации
проектных решений в геометрии**. Рисование — способ ввода, а не продукт.
Следствие: не строим слои, размерные цепи, узлы, экспорт DWG. Всё, что не
помогает зафиксировать и доказать решение, — вне scope.

## Разрыв: сделанное ≠ Модуль 2

| Сущность ТЗ | Что есть в коде | Разрыв |
|---|---|---|
| `DesignConcept` | планировка (`layout_documents`) | близко, но концепция шире геометрии |
| `ConceptOption` («три варианта») | поле `variant` есть, вариант ровно один | сравнения вариантов нет |
| `MaterialSelection` | `materials` + назначения | нет артикула, поставщика, цены |
| `FurnitureSelection` | `objects` — коробки с габаритами | нет каталога и стоимости |
| `RoomDecision` | — | нет |
| `DesignConstraint` | `warnings` | частично: фиксируют незнание, не ограничения |
| `ClientFeedback` | — | нет |
| `ConceptApproval` | публикация версии | версия есть, согласования клиентом нет |
| `BudgetImpact` | — | нет |
| `DESIGN_FREEZE` | — | выход модуля не реализован |

Из десяти позиций закрыты примерно две с половиной. Построен **фундамент**
Модуля 2, не сам модуль. Называть сделанное «модуль 2 готов» было бы неправдой.

## План внедрения: четыре шага

1. **Варианты вместо одного.** Поле `variant` уже есть. 2–3 варианта, показать
   рядом, дать выбрать. Закрывает `ConceptOption` и «three variants» из
   WF-M2-001. Самый дешёвый шаг — хранение и версии работают.
2. **Материалы и мебель как выбор, а не как форма.** Артикул, поставщик, цена.
   Закрывает `MaterialSelection` и `FurnitureSelection`, создаёт базу для шага 3.
3. **Влияние на бюджет.** `BudgetImpact` — то, что превращает редактор из
   рисовалки в инструмент управления. Прямая реализация коммерческой формулы
   устава «не переходите к следующему дорогому этапу вслепую».
4. **Согласование и `DESIGN_FREEZE`.** `ClientFeedback` → `ConceptApproval` →
   `DESIGN_FREEZE`. Механика публичной страницы КП из M1 переиспользуется.

## Критерии сдачи M2 после DEC-023 (позиционирование v2, §8)

Решение владельца 08.08.2026 (DEC-023,
`docs/positioning/REMHAOS_POSITIONING_V2_2026-08-08.md` §8) меняет условие
сдачи: **M2 сдан, когда позиционирование демонстрируемо, а не когда закрыт
список функций.** Четыре шага плана выше остаются планом работ; ниже — что
именно проверяется на приёмке.

| Условие §8 | Что закрывает | Где живёт |
|---|---|---|
| 1. «Во что обошлось» обязательно | шаги 2 и 3 плана — из «потом» в сдачу; без цен третья часть формулы v2 пустая | `MaterialSelection`, `FurnitureSelection`, `BudgetImpact` |
| 2. «Подписано» говорит по-человечески | «Версия 3 зафиксирована 12.08, утверждена клиентом» словами; хеш — в деталях для проверяющих | публикация версии, `DESIGN_FREEZE`, `lib/i18n/ru.ts` |
| 3. DXF-экспорт входит в сдачу | столп «без лицензий» не существует, пока файл не открывается у подрядчика | экспорт `lib/layout-studio` (A4 §3) |
| 4. Клиентская витрина решения | шаг 4 плана обязателен: страница согласования варианта клиентом | `ClientFeedback` → `ConceptApproval`, механика публичной страницы M1 |
| 5. Язык интерфейса = язык позиционирования | строки `layoutStudio` («локальный M2-прототип», «синтетический набор данных») переписываются на продуктовые при сдаче | `lib/i18n/ru.ts` |
| 6. Демо-сценарий — артефакт сдачи | скрипт 10-минутного показа бриф → паспорт → риски → КП → планировка → вариант → зафиксированная версия, прогоняется на живой сборке | расширение `DEMO.md` |

Граница не двигается: в сдаче M2 по-прежнему нет фотореалистичного рендера,
записи DWG, паритета с CAD и конструктивных узлов (A4 §2, CHARTER §16).
Публичное имя редактора при сдаче — **«Планировки»**; слово «CAD» в
пользовательских строках не используется (DEC-023).

## Что должен решить владелец (Codex не принимает эти решения — CHARTER §19)

1. **Записать OWNER DECISION об открытии M2** в `REMHAOS_DECISION_LOG_v1.md`.
   Устно решение принято; §20 требует именно записи. Без неё следующий
   исполнитель прочитает «Do not build» и будет прав.
2. **Подтвердить границу** «поверхность фиксации решений», а не CAD. От этого
   зависит, чего мы не строим. Если нужен именно CAD — это другой продукт и
   другой устав.
3. **Обновить строку M2 в READINESS MATRIX** на фактическое состояние.
4. **Решить судьбу двух демо-страниц** `/app/layout-studio/*`. Снос правилен для
   продукта, но на них стоят все 49 браузерных доказательств приёмки: после
   сноса они будут ссылаться на несуществующие адреса. Либо сносим и понижаем
   статус этих строк реестра, либо оставляем до переноса доказательств.
5. **Вне модуля 2:** в основном продукте 20 уязвимых зависимостей, 1 критическая,
   включая Next.js.
