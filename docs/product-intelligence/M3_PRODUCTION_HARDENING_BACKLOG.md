# M3 Production Hardening — backlog

**Статус:** принят решением владельца 11.08.2026 вместе с закрытием #79.
**Правило:** каждый пункт **обязателен до внешнего production-пилота M3** и
**не блокирует** разработку M4. Пункт закрывается кодом с тестом, не галочкой.

Источник — внешнее ревью #79. Номера сохранены из него, чтобы обсуждения не
расползались по двум нумерациям. Пункты 1 и 3 из того списка выполнены в самом
#79 (отзыв M3-only RPC; утечка package scope + детерминированная метка) и здесь
не повторяются.

| # | Что | Почему отложено |
|---|---|---|
| 2 | Чтения M3 в матрице; при выключенном M3 прямой Data API не отдаёт draft/source/sheet данные | Читающие RPC общие с M2 — отозвать нельзя; нужен gate внутри RPC, то есть авторитетный DB-state, который сам вынесен в отдельное решение (см. ниже) |
| 4 | Отдельная безопасная read-only проекция для released archive; полный `get_project_workspace_read_v9` архивом не является | Поверхности Project Archive ещё нет; проекция строится вместе с ней. Продуктовая основа — §1.7 решения DEC-026/027 |
| 5 | `sourceRevisionIds` выводятся сервером из допустимых проверенных источников и входят в composition, snapshot token и semantic hash | Клиент уже шлёт только токен, поля уже в токене и хеше — но всегда пусты: источники попадают в граф только через воркерный `ingest_source_graph`, которого нет. Пункт активируется вместе с воркерным контуром |
| 6 | Создание graph version и baseline — одна транзакционная операция либо durable orchestration с resume | Детерминированная метка (сделано в #79) уже даёт resume через replay того же `commandId`. Остаток — SQL-дверь одной транзакцией против гонки «новая команда при осиротевшей версии» |
| 7 | Четыре теста: replay того же `commandId` → прежний успех; новый `commandId` со старым токеном → `stale_state`; сбой после первого шага → ничего не остаётся; потеря ответа после commit → повтор возвращает прежний результат | Доказывают семантику пункта 6; делать вместе с ним. Частично покрыто: детерминизм метки и stale-token уже под тестами |
| 8 | При включённом M3 `authenticated` не получает сырые descriptor-RPC (`publish_project_baseline`, `publish_production_package_version`); публична только orchestration-дверь | Правило полноты живёт в приложении: прямой вызов с грантом может опубликовать частичный baseline. Лечение — перенос composition в SQL-дверь; сегодня гранты существуют только в одноразовых средах |

**Связанное отдельное решение (не пункт backlog, а его предпосылка):**
production-включение M3 — один авторитетный DB-state с аудитом (кто, когда, на
каком основании), env-флаг поверх него как дополнительный hard-off. Грант из
`enable-m3-publication.sql` — механизм одноразовой среды, production им не
включается. Пункты 2 и 8 технически зависят от этого решения.

**Определение готовности пункта:** миграция/код + DB4-сценарий или юнит-тест,
падающий при регрессе + строка в этом файле переведена в «закрыто» со ссылкой
на PR.
