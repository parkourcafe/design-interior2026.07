## Шаг 0 — governance, до любого кода

M3 был заперт двумя записями: A4 §1.2 («M3 и M4 остаются закрытыми, их
открытие требует отдельного аддендума») и строка матрицы `Do not build, P3`.

**Аддендум A5 уже существует — НЕ ПИШИ ВТОРОЙ.** Он подготовлен контуром M3:
`docs/canonical/remhaos-v1/REMHAOS_ADDENDUM_A5_M3_OPENING.md` на ветке
`claude/new-session-j82fk1`, вместе с `docs/m3/M3_NEW_SESSION_HANDOFF_2026-08-08.md`.
Владелец подтвердил подпись словом 09.08.2026. В истории M2 два чата
параллельно написали два аддендума и один пришлось отзывать — не повторяй.

Твой шаг 0 — проверить, что подпись **записана**, а не только произнесена:
поле «Подписал/Дата» заполнено, механические правки из самого A5 выполнены
одним коммитом (журнал решений — следующий DEC, строка M3 матрицы, статусы
workflow, оба бренда), ветка запушена и едет в канонический пакет на `main`.
Чего не хватает — доделай в контуре, владеющем каноническим пакетом, а не
параллельным файлом. Код M3 начинается после этого.

## Объём M3 P0 — из плана, не выдумывать

Intake документации PDF/JPG/PNG/CSV/XLSX · связи room/sheet/specification ·
ревизии · completeness/conflict review · baseline · immutable
`Released Production Package`. **Native CAD/BIM authoring не строится** —
это A4, не обсуждается.

## Что уже существует — не строить заново

Главный урок M2: параллельный контур едва не построил модуль второй раз,
потому что не знал о существующем. Проверяй, потом строй:

- машинерия sources → baseline → release → distribution → acknowledgement
  уже живёт в `projectceo_product` со времён вертикального среза Kora; живой
  сценарий — `tests/ap1/e2e/run-five-sessions.zsh`;
- вход из M2: `publish_m2_m3_handoff` / `M2ToM3Handoff` — M3 принимает
  **только** persisted exact handoff (approved commit revision, layout с
  подписью `sha256:<hex>`, selection revisions, budget). Обходов не строить;
- образец командного контракта — `command-contract.ts`: `.strict()`,
  `superRefine`, серверный пересчёт подписи, идемпотентность;
- `MODULE_3_REPORT.md` в корне — это **другой** «модуль 3» старой M1-линии
  (Project Room из принятого КП). Не путать и не трогать.

## Неподвижные правила (AGENTS.md)

RLS deny-by-default · human operations без service role · actor/org/project/
package/role выводятся server-side · published versions, approvals, releases,
handoffs и audit — append-only · повторные запросы идемпотентны · строки UI в
`lib/i18n/ru.ts` · деньги — integer RUB · миграции только additive, каждая —
строка в `tests/ap1/environment/migration-ledger.sha256`.

## Метод и гейты

Agent Loop: RED → GREEN → REFACTOR/security review → полные гейты →
evidence/отчёт. Гейты: `npm run lint` (0 ошибок, предупреждений не добавлять),
`typecheck`, `test`, `build`; CI на каждый пуш сам гоняет DB4 на PostgreSQL 16
и 17. `npm run test:cycle7` **красный намеренно** — внешний реальный пакет не
предоставлен; не чинить, не удалять, не объявлять зелёным. Запуск M3 этого
требования не снимает.

## Дисциплина отчётности

Каждое заявление в отчёте обязано иметь коммит, тест или лог. Чужие отчёты
проверяй по коду: в истории M2 «фактически работающий producer» отсутствовал
в репозитории, «324 теста» оказались 1013, а «уже существующий механизм
предупреждений» не существовал. Свои отчёты проверяй тем же способом — в той
же истории автор дважды поймал себя: на коммите, заявившем правку, которой в
нём не было, и на хеше не того архива.

## Не строить

CAD/BIM-паритет (A4 §1.1) · широкий M4 · marketplace, credits, AI-router,
собственная ЭП · production adoption без отдельного решения.

Если чего-то из перечисленного нет на `main` — остановись и спроси, а не
досочиняй.
