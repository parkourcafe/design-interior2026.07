## 1. Исходная проблема: две линии без общей точки

Стартовая постановка требует шесть источников. На момент начала работы
**четыре из них отсутствовали** в ветке, где велась работа, а канон, который
требуется читать, отсутствовал на `main`.

| Источник | Ветка `claude/new-session-j82fk1` (линия `223ef8e`) | `origin/main` до слияния |
|---|---|---|
| `AGENTS.md` | нет | есть |
| `docs/canonical/remhaos-v1/` | есть | **нет** |
| `wave-3/MASTER_EXECUTION_PLAN.md` | нет | есть |
| `adr/0004–0007` | нет | есть |
| `M2_CLOSEOUT`, `M2_P0_NEW_CHAT_HANDOFF` | нет | есть |
| `m2-to-m3-handoff/` | нет | есть |

Это ровно то расхождение, которое ADR-0006 описал словами «канонический пакет
находится на линии `223ef8e`, которая не является предком `main`… два
параллельных контура читали два разных источника истины». Проверено
`git ls-tree` по обеим линиям.

**Разрешено решением владельца 09.08.2026:** работа переносится на `main`,
канон вливается PR #69.

## 4. Поправка к моему предыдущему отчёту

Отчёт от 08.08 (`docs/m3/M3_GATE_CHECK_2026-08-08.md`, ветка `…-j82fk1`)
утверждал: **«`DESIGN_FREEZE` в коде отсутствует вообще»**. Это верно для линии
`223ef8e` и **неверно для `main`**. На `main` вход M3 реализован:

- `createM2ToM3Handoff` требует approved commit, layout со статусом `published`
  и подписью `sha256:<hex>`, совпадающей с выбранным вариантом, approved
  selection revisions и чистый бюджет — `lib/project-intelligence/application/m2-to-m3-handoff/index.ts:186–253`;
- покрытие: `tests/project-intelligence/application/m2-to-m3-handoff.test.ts`,
  серверная сторона — `supabase/migrations/20260802090000_projectceo_m2_client_review_m3_handoff.sql`
  и `tests/db4/33_m2_client_review_m3_handoff_operations.sql`;
- `M2_CLOSEOUT_2026-08-08.md`: «Неизменяемый Approved Commit… Exact-version
  handoff в M3».

То есть обязательство №1 записки о влиянии A4 (freeze ссылается на
`versionId` + семантический хеш) на этой линии **исполнено**, и отдельный
механизм заморозки в M3 не нужен. Ошибка была следствием грепа по ветке, где
этого кода нет; вывод «дефект M2» снимается.

## 5. Расхождение объёма M3 — вынесено владельцу, решено

Два канонических документа описывали разные модули:

- `REMHAOS_M3_IMPACT_NOTE_2026-08-08.md` — гибрид: генератор листов из
  подписанной модели + реестр внешних файлов, выход `DOCUMENTATION_RELEASE`;
- `MASTER_EXECUTION_PLAN` §M3 + `AGENTS.md` — intake PDF/JPG/PNG/CSV/XLSX,
  links, revision, completeness/conflict, baseline, immutable **Released
  Production Package**; «native CAD/BIM authoring не строится».

**Решение владельца 09.08.2026:** P0 — строго из плана; гибрид фиксируется в A5
как пост-P0. Исполнено в A5 §1.1 и §1.3: граница названа явно, записка остаётся
действительной как подготовительная, противоречия между документами больше нет.

## 6. Дубль governance — снят

В ветке `claude/new-session-j82fk1` 08–09.08 был подготовлен и устно подписан
документ A5 с гибридным объёмом. Он **отозван** — прямой пометкой в шапке новой
редакции. Причина: объём взят из подготовительной записки, документ не видел
`AGENTS.md`, плана и реализованной двери M2→M3.

Сопутствующее наблюдение, не требующее действий: позиционирование v2
существует в двух экземплярах — `docs/positioning/REMHAOS_POSITIONING_V2_2026-08-08.md`
(влит в `main` через #69, каноническая копия) и
`docs/brand/REMHAOS_POSITIONING_v2_2026-08-08.md` в ветке `…-j82fk1` (никуда не
вливается). Формулировки DEC-023 в двух журналах различаются; на `main`
действует версия из #69.
