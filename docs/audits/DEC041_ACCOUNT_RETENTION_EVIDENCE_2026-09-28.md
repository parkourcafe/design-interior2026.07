# DEC-041 §2 — удаление аккаунта с 90-дневным сроком «только для чтения»: evidence

**Основание:**
- DEC-040: 90 дней read-only и полного экспорта;
- DEC-041 §2: удаление аккаунта входит в этот срок;
- DEC-044 (a): ответ владельца от 28.09.2026 — в эти 90 дней вход только для чтения.

Реальное удаление данных (purge), production, merge и deploy в разрешение не входят.

## Что изменилось для людей

- **Дизайнер** нажимает «Удалить аккаунт» — данные больше не стираются сразу. Создаётся заявка, срок — 90 дней.
  В срок дизайнер входит, видит проекты, скачивает полный экспорт и может отменить удаление. Менять ничего нельзя.
- **Клиент** открывает выданное КП по ссылке, но ответить на него не может («КП в архиве»).
  Бриф по ссылке не принимается.
- **Оператор** может поставить legal hold или платный архив и получить план purge. План ничего не удаляет.

## Как это обеспечено

**База (источник истины):**
- `account_retention_cases`: одна активная заявка на дизайнера, `purge_after = requested_at + 90 дней`.
- `account_retention_events`: append-only журнал с автором и причиной.
- `account_retention_projects`: снимок проектов на момент заявки. Проект нельзя вывести из срока, переписав
  его на другого владельца: проверки идут по снимку, по старой и новой строке.
- Триггер `guard_account_retention_read_only` запрещает запись API-ролям в 14 таблицах (список — в дизайне, §2а).
- Команды ProjectCEO и интеграций по проекту из снимка не завершаются: запрет на трёх журналах команд.
- `request_account_deletion` идемпотентна: повтор возвращает ту же заявку, advisory lock на дизайнера.
- Отмена разрешена до срока. Legal hold отмене не мешает: отмена сохраняет данные.
- Legal hold и платный архив ставит только `service_role`, под тем же замком и только на активную заявку.
  Прошедшая дата архива отклоняется.
- `record_account_purge_plan` принимает только план с `destructive = false`.

**Приложение:**
- `DELETE /api/account/delete` создаёт заявку через сессию дизайнера, без service role.
- `/api/account/retention`: статус и отмена с понятной причиной отказа.
- `/api/account/export`: постранично и под RLS дизайнера. Внутри проекты, ответы, риски, все версии паспорта,
  КП, договоры (метаданные), события, комнаты, участники, задачи, планировки и команда студии.
  Токены доступа вырезаны.
- Маршруты брифа закрываются до любой записи, включая загрузку файла. Ответ на КП получает 409
  `proposal_archived` до записи события. Страница КП в срок не пишет `proposal_viewed` и не создаёт черновик.
- В кабинете показан баннер «только для чтения».

## Известные ограничения (решения владельца не требуют, если не сказано иное)

1. Записи моста Telegram (события, очереди) по проекту в сроке не запрещены. Мост по умолчанию выключен
   (DEC-044 (c)).
2. Загрузка плана дизайнером (`authenticated-plan-upload`) кладёт объект в хранилище до проверки срока.
   Таблицы запись отклоняют, объект остаётся сиротой.
3. **Нужно решение владельца:** после 90 дней заявка остаётся `requested`. Purge не разрешён, другого выхода
   у оператора нет.
4. Файлы в экспорт не вкладываются, экспорт перечисляет их пути. Данные ProjectCEO в экспорт не входят.
