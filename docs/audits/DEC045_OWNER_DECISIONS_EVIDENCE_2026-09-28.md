## (a) После 90 дней

- Миграция `20260928120000_account_retention_expiry.sql`.
- Статус `expired`: одна живая заявка на дизайнера — в сроке или после него.
- Fail-closed: заявка `requested` с истёкшим сроком везде считается `expired`, даже до перевода статуса.
- Вход закрыт:
  - `proxy.ts` уводит `/dashboard` на `/account-closed` на каждом запросе, включая клиентские переходы;
  - layout делает то же;
  - экспорт отвечает 403 `account_closed`, а если статус не прочитать — 503.
- Данные остаются только для чтения, КП по ссылке открывается «в архиве», бриф не принимается.
- Оператор (`scripts/account-retention-expiry.ts`):
  - `sweep` — перевод статуса с записью `expired` в журнал;
  - `list` — список;
  - `restore` — только после срока, с причиной и именем оператора; legal hold не мешает.
- Проверка базы нашла и закрыла ошибку: legal hold и платный архив не ставились на заявку после срока.

## (b) Ключ воркера файлов

- Миграция `20260928130000_file_intake_worker_identity.sql` заводит **узкую** роль `pi_telegram_file_worker`.
  - Роль может ровно две вещи: создать запись о файле и отметить загрузку.
  - Итог проверки файла она не ставит, таблиц не видит.
  - Логин-роль API `authenticator` получает членство в ней.
  - Миграция сама проверяет, что лишних прав у роли нет.
- Первая версия отдавала API широкую `pi_worker_executor`. Ревью показало, что утёкший ключ позволил бы
  самому пометить свой файл «чистым» и подделывать задания интеграций. Роль сужена, DEC-045 (b) уточнён.
- `createFileIntakeWorkerClient()` требует ключ с ролью `pi_telegram_file_worker` и будущим `exp`.
  Ключ с другой ролью, без срока или просроченный отклоняется до захвата вложений.
- Инструкция: `docs/canonical/remhaos-v1/REMHAOS_FILE_INTAKE_WORKER_KEY_RUNBOOK.md`.

- Миграция `20260928140000_file_intake_worker_actor.sql` копирует тела обеих функций R1 без изменений, кроме автора.
  - Независимое ревью сравнило тела построчно: отличаются только строки автора, 3 и 4.
  - Автор берётся из роли вызова: под `pi_telegram_file_worker` — `system:telegram-attachment-worker`,

  с поддельным ключом `telegram-attachment:*` остаётся подписан Google Drive.
