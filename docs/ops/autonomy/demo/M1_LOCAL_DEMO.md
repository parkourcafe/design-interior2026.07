# M1: демонстрация «бриф → КП → ответ клиента»

Дата: 28.09.2026 · задача T-REMH-01 (R3) · ветка `claude/autonomy-remh-01`.

Здесь две части:

- **A** — локальный прогон без базы и сети. Его может запустить любой человек за минуту.
- **B** — чек-лист владельцу на 5 минут кликов по живому сайту.

Часть A не заменяет часть B.

## A. Локальный прогон (TESTED_LOCAL)

```bash
npm ci
npm run demo:m1:local
```

Файл: `tests/release/m1-local-demo.test.tsx`. Данные синтетические:

- клиент «Демо-клиент», 62 м², «Синтетический город»;
- ставка 3000 ₽/м² — это демо-значение, а не цена продукта.

LLM и Supabase заменены моками. Прогон реально исполняет код приложения:

- `runRiskPipeline`, `calcPrice`, `buildProposalSections`;
- server action `sendProposal`;
- серверный компонент `app/p/[public_token]/page.tsx`, отрендеренный в HTML через `react-dom/server`;
- маршрут `POST /api/proposal/respond`.

Стенограмма прогона от 28.09.2026 (вывод команды, без правок):

```
1. Бриф: 62 м², срочность=urgent; LLM ok=true
   · риск [rule/function] Обсудить закрытые системы хранения, которые сохраняют минималистичный вид.
   · риск [rule/function] Обсудить второй санузел / раздельный санузел / два умывальника — что позволяет планировка.
   · риск [llm/technical] Уточнить состояние стяжки
2. КП: пакет=full_plus_supervision, цена 261000–319000 ₽, секций 10
3. Черновик по /p/demo-token → 404 (клиент не видит до «Отправить»)
4. «Отправить» → proposals.status=sent, событие proposal_sent
5. Клиент открыл /p/demo-token: 10 секций, цена видна, кнопки «Принять предложение» / «Обсудить» / «Запросить правки»; событие proposal_viewed
6. Клиент: «Принять» → proposals.status=accepted, projects.status=proposal_accepted
7. Повторное открытие: «Вы приняли это предложение»
   события: proposal_sent → proposal_viewed → proposal_accepted
```

Карточка `llm/technical` пришла из мока, настоящего вызова модели не было.

**Что этот прогон не проверяет:**

- клики и JavaScript в браузере: кнопки отрендерены, но не нажаты, ответ отправлен прямым вызовом маршрута;
- RLS и триггеры реальной базы;
- magic-link вход;
- настоящий LLM-провайдер;
- печать `@media print`.

## Найдено при подготовке: «Отправить» на свежем проекте упирается в enrollment

Факты:

- `sendProposal` требует утверждённый approval request на `project_passport`: `app/dashboard/projects/[id]/proposal/actions.ts:191`.
- Проверку делает RPC `projectceo_platform_api.list_approval_requests`. Эта функция авторизует через `_authorize_project_human`, поэтому проект уже должен быть в ProjectCEO: `supabase/migrations/20260831170000_projectceo_platform_approval_request_actor_projection.sql`.
- Approval request создаётся в рабочем пространстве ProjectCEO, во вкладке «паспорт»: `components/projectceo/m1-project-panel.tsx:279-286`.
- В `app/` и `components/` никто не вызывает `/api/projectceo/enroll`. Браузерный харнесс AP5 записывает проект в ProjectCEO прямым RPC в `tests/ap5/global-setup.ts:146-163`. Там же прямо сказано, что у операции «нет HTTP-поверхности — ни маршрута, ни элемента».

Интерпретация: на **свежем** проекте, созданном по DEMO.md, шаг 7 «Отправить» остановится на сообщении «Сначала получите утверждённый approval request для паспорта проекта в ProjectCEO». Кликами это не обойти. Это тот же вопрос, что блокер B3 в `docs/ops/autonomy/tasks/T-REMH-01.md`, только теперь видно, что он ломает и демо M1. Решение за владельцем: где кнопка enrollment и нужна ли эта проверка для отправки КП в пилоте.

## B. Чек-лист владельцу — 5 минут на живом сайте (NOT_VERIFIED)

Сайт из этой среды недоступен: прокси отдаёт 403. Поэтому пункты ниже проверяет владелец. Нужны два окна: обычное (дизайнер) и приватное (клиент). В брифе используйте вымышленные данные.

| # | Действие | Ожидаемо | ✓/✗ |
|---|---|---|---|
| 1 | Войти дизайнером, открыть `/dashboard`, нажать «Новый проект», ввести имя «Тест-демо» | На странице проекта есть ссылка `/i/…`. Если профиль не заполнен, вместо ссылки блок «Заполнить профиль» | |
| 2 | В приватном окне открыть `/i/…` и пройти бриф вымышленными ответами, отметив согласие на ПДн | «Завершить» срабатывает, ошибки нет | |
| 3 | В окне дизайнера обновить страницу проекта | Виден паспорт и карточки рисков в тоне «Возможный риск…». Если LLM недоступен — баннер деградации и rule-карточки | |
| 4 | Принять 1–2 карточки, нажать «Собрать коммерческое предложение» | Секции заполнены, блок «Стоимость» — диапазон в ₽ (или его нет в режиме «без цены») | |
| 5 | Нажать «Отправить» | **Либо** статус «отправлено», **либо** сообщение «Сначала получите утверждённый approval request…». Запишите, что именно появилось: второй вариант подтверждает находку выше | |
